## 1. CAD 场景 A 双路径收口（真机验收 + 调参清单）

### 1.1 双路径定义与现状

```
输入 .dwg（场景 A：单文件多图框）
  ├─ 路径① COM 窗口级（质量最高）：cad-convert.ps1 mode=split
  │     块名/多段线候选 → 图幅匹配（含 m→mm 换算）→ 去重聚类 → Z 序 → 图号 →
  │     逐框 SetWindowToPlot + PlotToFile（DWG To PDF.pc3，A4 横向）→ Node 合并
  ├─ 路径② ODA 整文件 → PDF 级分割（cad.js 已有编排）
  └─ 路径③ PDF 级兜底（已实现、已测试）：直接吃已有 PDF（或 ODA 产出）
```

**P3 目标**：把路径① 从「骨架」推进到「真机验收通过 + 调参清单固化」；用路径③ 在本机对真图 PDF 替代品做同口径验收；两路径对同一图集输出可比对。路径① 的代码改动仅限 §1.3 的调试增强，**不重写流水线**。

### 1.2 真机验收方案（D5 COM / D3 PDF 级 / D4 ODA，沿用 P1 §5.2 编号）

**涉密样例（仅路径引用，绝不读取内容入库）**：
- 场景 A：`E:\工作\2026\20261019Visio插件制作\图纸例子\盘溪变-二次图纸.dwg`、`金亭变-110GIS扩建二次图纸.dwg`
- 场景 B：`白云变电站 D0101 竣工图 20 张`、`Z-T0101 土建 5 张`（目录）

**D5（COM 真机，在有 CAD 的机器执行）检查点清单**：

| # | 检查点 | 工具 | 通过标准 |
|---|---|---|---|
| D5-1 | 探测环境 | `probe.ps1 -Json '{"refresh":true}'` | `cad.platforms[].present=true`；记录 progId/curVer/`cad.pc3` 打印设备清单（含 `* To PDF.pc3` 与可用媒体名） |
| D5-2 | 冒烟-分割 | `tools\com-smoke.ps1 -Json '{"dwg":"<盘溪变>","outputDir":"..."}'`（扩展后支持 `-Mode split|merge|both`） | 退出码 0；engine JSON `ok:true`；`frames[].drawingNo` 与图签人工核对一致；`frames.Count` 与人工数框一致 |

| D5-6 | 三平台轮测 | 同一 D5-2 在 AutoCAD/中望/浩辰各跑一次 | 每平台通过或记录差异（pc3 名/媒体名/SetWindowToPlot 签名）回填 §1.4 调参表 |

**D3（PDF 级真图，本机可跑）**：用户把 `图纸例子` 在任一有 CAD/打印机的机器上**打印成整图 PDF** 放入 `tests-local\pdf-export\`（git 忽略，与涉密图纸同待遇：只引用路径、不进日志内容）。`tests-local\accept-pdf.ps1` 对每份 PDF 跑 `splitPdfFile`，输出 `{文件, 帧数, 图号列表, 排序, 纸型}` 报告；人工比对：帧数与图框数一致、图号序列与图签一致、页序符合 Z 形/图号规则、加长幅面（A4×3 等）识别正确。

**D4（ODA）**：有 ODA 机器跑 `accept-oda.ps1`（场景 A：整文件转换后 PDF 级分割；场景 B：整目录），检查点同 P2 §5.3。

**双路径一致性（D5 与 D3 都通过后）**：对同一张多图框图纸，路径① 的 `frames[].drawingNo` 序列与路径③ 的 `result.frames[].drawingNo` 序列比对：
- 完全一致 → 通过；
- 帧数不一致 → 分别打印两路径的识别明细（坐标/图幅/置信度）定位差异，走 §1.4 调参闭环；
- 仅个别图号不一致 → 记录到 `docs\兼容矩阵.md` 已知限制，不影响验收结论（两引擎文本来源不同：COM 读实体/属性，PDF 读 `getTextContent`）。

### 1.3 cad-convert.ps1 的 P3 增补（最小改动）

1. **`listBlocks` 调试输出**：payload 增加 `"listBlocks": true` 时，split 流程在识别前把模型空间全部块名（`EffectiveName`）清单写进 result（`blocks:[...]`，去重排序，上限 500），并附带 `candidates`/`kept` 明细（已有字段）。用途：真机第一跑时发现「样例图框块名不在默认通配清单」→ 回填 `config.frameBlockNames`。**此输出含图纸元信息，不涉密内容**，可入日志。
2. **`mode=catalog`**：不打印、只返回 `{frames:[{drawingNo, texts:[{text,x,y}]}]}`（§2.2 目录表数据源）。实现：复用 `Get-FrameCandidates`/`Merge-FrameCandidates`/`Sort-Frames-Z`，对每框输出**全框**文本项（相对图框坐标，`Get-TextItems` 已有），图名/比例提取在 Node 侧统一做（与 PDF 级同一套规则，避免两处实现漂移）。
3. **媒体名候选表扩展**（`Set-A4LandscapeMedia`）：追加 `'ISO A4'`、`'ISO_A4'`；同时在 D5-2 失败日志中输出**当前 pc3 的可用媒体名清单**（遍历 `layout.GetCanonicalMediaNames()` 写入 error.hint），一次失败即可完成调参。

### 1.4 调参清单（识别容差 / 图号正则 / 排序 —— 全部可配置，真机校准后固化默认值）

| 配置键 | 当前默认 | 调参对象 | 校准方法与建议区间 |
|---|---|---|---|
| `frameToleranceMm` | `2`（mm） | 图幅匹配容差 | D3 真图若出现「少识别一框」：先查报告里候选矩形的实测尺寸，容差上调至 3–5；若「多识别噪声框」：下调至 1。建议区间 1–5 |
| `frameBlockNames` | `['*图框*','A0','A1','A2','A3','A4','*TK*']` | 图框块名通配 | D5-2 用 `listBlocks:true` 拿到真机块名清单 → 取图框块名加入（如 `*_TK_*`、`图框-*`）；PDF 级不用此键 |
| `frameSizes` | 16 项标准幅面表（含加长） | 图幅尺寸表 | 真图出现非标幅面（如 A2+1/2 未收）→ 增补 `{name,width,height}`；**勿删默认项** |
| `drawingNoPatterns` | 两则（`图号/编号/图别` 前缀 + 裸编号 ≥4 位数字） | 图号提取正则 | 图签实际格式（如「图号 D0101-01」无冒号、或「图 号：」全角空格）→ 前置一条更精确的模式；正则按 `compileDrawingNoPatterns` 语法（忽略大小写、捕获组 1 优先） |
| `titleBlockZone` | `[0.6, 0, 1.0, 0.25]`（相对图框右下象限，原点左下） | 图签区范围 | 图号未提取到（`E1013` 告警）→ 用报告中的文本项坐标散点核对图签实际位置，调整 x0/y1 |
| `sortMode` | `'drawingNo'` | 排序 | 图号不可靠的图集改 `'filename'`；分割场景排序 = 先 Z 形平面序（`zOrderFrames`，列容差 = 中位宽度 × 0.5，可用 `columnTolerance` 覆盖）再稳定按图号/文件名 |
| `pc3` | `''` → `'DWG To PDF.pc3'` | 打印设备 | D5-1 的 `cad.pc3` 清单选实际设备名回填（中望/浩辰为各自 `* To PDF.pc3`） |
| `cadTimeoutMs` | `300000` | 单文件 COM 超时 | 大图框文件超时 → 上调；单图框打印通常 <10s，300s 已留裕量 |

**调参闭环协议**（写入 `tests-local\accept-pdf.ps1` 报告头）：
1. 每次验收输出 `识别参数快照`（上述键的有效值）+ `识别明细`（每框坐标/图幅/置信度/图号原文）；
2. 人工比对失败项 → 改 `runtime\ui-config.json`（面板 DiagTab 可改白名单键）→ 重跑 → 记录「参数变更 → 结果变化」；
3. 收敛后把最终参数固化进 `ops.js DEFAULT_CONFIG` 与本文档，并在 `docs\兼容矩阵.md` 登记「已校准（样例集）」一行。

## 2. 图纸目录表：`suite.cad.catalog`

### 2.1 命令契约

| 项 | 内容 |
|---|---|
| 命令 | `suite.cad.catalog`（面板命令；同步执行，返回即完成，不走任务注册表——单次规模有上限，见下） |
| 参数 | `{ input: string（.dwg 或 .pdf 单文件，或目录，必填）, output?: string（xlsx 路径；缺省 outputRoot\catalog-<时间戳>.xlsx）, sort?: 'drawingNo'\|'filename'（默认 drawingNo）, engine?: 'auto'\|'com'\|'pdf'（默认 auto，规则同 cad.convert） }` |
| 返回 | `{ ok:true, result:{ outputPath, engine, sources:[{file, frames, withDrawingNo}], rows: N, sheets: M, fields:{drawingNo,title,frameSize,scale,count} 命中统计, warnings:[...] } }` |
| 错误码 | `E1021/E1023/E1041`（路径/参数）、`E1001`（无引擎）、`E1012`（无图框）、`E1061 CATALOG_EMPTY`（未提取到任何目录字段）、`E1062 CATALOG_WRITE_FAILED`、`E1051` |
| 规模上限 | 单任务 文件 ≤100、图框合计 ≤500（`catalogMaxFrames`）；超限报 `E1041` 提示分批（目录表是轻量同步操作，防止长阻塞命令通道） |

**面板**：CadTab 增加「生成图纸目录表」按钮（选中文件/目录后可用，走 `suite.cad.catalog`）；结果区显示 xlsx 路径 + 行数 + 图号命中率，支持「在文档中心查看」。

### 2.2 数据获取（引擎只提供文本，抽取逻辑统一在 Node）

| 输入 | 数据源 |
|---|---|
| `.pdf` 或 ODA 产出 | 复用 `pdf-split.js`：`detectFramesOnPage`（图框+图幅）→ `getPageTextItems`（整页文本项）→ 每框 `toFrameRelativeItems` |
| `.dwg` + COM | `cad-convert.ps1 mode=catalog`（§1.3-2）：返回每框相对坐标文本项与图幅、图号 |
| `.dwg` + ODA | ODA 整文件 → PDF → 同上（cad.js 已有 `convertWithOda` 编排，目录表流程内复刻调用） |
| `.dwg` 无任何引擎 | `E1001`（同 cad.convert 语义） |

### 2.3 目录字段抽取（`drawingNo.js` 扩展 `extractCatalogFields(items, options)`，纯函数、两引擎共用、可单测）

每框输入：相对图框坐标文本项（0..1，原点左下）。抽取规则（全部可配置）：

| 字段 | 规则 | 配置键（默认） |
|---|---|---|
| `drawingNo` 图号 | 沿用 `extractDrawingNo`（图签区 + 两则正则） | `titleBlockZone=[0.6,0,1.0,0.25]`、`drawingNoPatterns` |
| `title` 图名 | 图名区（图签区上方）：`titleNameZone=[0.3,0.25,1.0,0.55]` 内取**最长连续中文文本行**（≥2 字），排除纯数字/比例/日期行；未命中回退文件名（去扩展名） | `catalogTitleNameZone` |
| `frameSize` 图幅 | 图框匹配结果 `match.name`（A4/A3/A0×2…），横竖按 `orientation` 标注 | `frameSizes/frameToleranceMm` |
| `scale` 比例 | 全框文本正则：`比例\s*[:：]?\s*(\d+\s*[:：]\s*\d+)` → 无前缀裸写 `\b(\d+[:：]\d{1,4})\b`（排除图号形如 `D0101-01` 的连字符干扰） | `catalogScalePatterns` |
| `count` 张数 | 同 `drawingNo` 图框数（同一来源文件内统计）；图号缺失时按 `title+frameSize` 组合统计 | — |

行结构：`{ seq, drawingNo|null, title, frameSize, orientation, scale|null, count, source, pageIndex?, window? }`。排序：`sort:'drawingNo'` 时图号优先（null 排后，再按文件名），`'filename'` 按来源文件+页序（= P1 §3.4 语义）。

### 2.4 xlsx 落盘（`host/ops/cad-catalog.js` + `engines/catalog-write.py`）

- **写表引擎选择**：Python venv（openpyxl 已核实可用，P2 交付）优先；venv 不可用时降级 **CSV**（纯 Node 写出，同目录同名 .csv），结果 `engine:'python'|'csv'` 并告警「CSV 无样式」。
- **新脚本 `engines/catalog-write.py`**（不复用 office-python.py，保持编辑引擎单一职责）：输入 `-Json '{"path":..., "sheets":[{"name":"汇总","rows":[{...字段}]}], "title":"..."}'`；openpyxl 写：表头加粗 + 边框 + 冻结首行 + 列宽自适应（图名 32、图号 18、其余 10）+ 首列序号。
- **工作表组织**：来源文件数 >1 时：`汇总` sheet（全部行，含「来源」列）+ 每个来源文件一个 sheet（名称=文件名去扩展名，截断 31 字符去重）；单来源只有 `汇总`。
- **输出路径**：`output` 指定则校验 `.xlsx` 扩展 + boundary(write)；缺省 `outputRoot\catalog-<时间戳>.xlsx`（outputRoot 语义同 cad.convert）。CSV 降级时若 `output` 指定了 .xlsx 扩展则改 .csv 并在 result 标注。
- 目录表是**新文件**，不触发备份；写失败 `E1062`（磁盘满/占用，hint 提示关闭占用进程）。

## 3. 批量队列（CAD 多文件/多文件夹）

### 3.1 入口扩展：`suite.cad.convert` 增 `inputs` 数组

参数 JSON 扩展（`input` 语义与行为**完全不变**）：

```jsonc
{ "mode": "merge|split",                          // 队列内所有条目同一模式
  "inputs": [ "<文件或目录>", "<文件或目录>", ... ],   // 新：1–100 项（queueMaxItems）
  "input": "<单文件或目录>",                        // 既有：单任务（与 inputs 互斥，同时给报 E1041）
  "output": "<目录或 .pdf>", "paper", "sort", "parallel"  // 同既有
}
```

- 解析规则：`inputs` 每项 = 一个独立子任务；merge 条目必须是目录、split 条目必须是单文件（.dwg/.pdf）；每个子任务独立走 `prepareCadSpec`（含探测/输出路径推导：目录输出时 `<mode>-<时间戳>-<两位序号>.pdf`，多文件夹 merge 每个文件夹一个 PDF）。
- 返回：`{ taskId, kind:'cad.queue', mode, engine, items:[{index,input,output}], itemsTotal }`（立即返回）。

### 3.2 队列任务语义

- 复用 `TaskStore`：任务 `kind:'cad.queue'`，状态机不变（`queued → running → converting → merging → done|failed|cancelled`）；**每子任务再独立注册一个 `kind:'cad.convert'` 的普通任务**（既有 `runCadTask` 直接跑，不改），父任务聚合子任务进度——这是对 tasks.js **零侵入**的方案：
  - 父任务 `progress.itemsDone/itemsTotal`（§3.3 扩展）+ `log` 摘要（每子任务完成/失败一行：`[2/5] merged-xxx.pdf ok`）；
  - 子任务照旧有自己的 taskId，面板/命令可分别轮询；父任务状态由聚合器推进：全部完成 → `done`（`failures:[{index,input,code,message}]` 记录失败项，**部分失败不算 failed**，语义同 suite.format.batch）；全部失败 → `failed`（E1033）。
- **取消**：取消父任务 → 递归 cancel 所有未终态子任务；取消子任务只影响自身（父任务继续，该子任务记 cancelled 入 failures）。
- 面板 CadTab：场景 A 支持多选文件（清单编辑器，一行一路径 + 「添加文件…/添加文件夹…」按钮，folder 选择器用 uiWorkspace.pickDirectory）；场景 B 支持多文件夹清单；进度条 = 子任务数 + 当前子任务名；每行条目状态徽标（queued/running/done/failed/cancelled）。

### 3.3 tasks.js 最小扩展（向后兼容）

- `initialProgress()` 增加 `itemsDone:0, itemsTotal:0`；`tick` 的 `numericKeys` 增加 `'itemsDone','itemsTotal'`。旧任务 snapshot 多两个 0 字段，无破坏。
- `create(meta)` 增加 `parentId` 可选字段（子任务归属，聚合器用）；`summary/snapshot` 透传。
- 聚合器：`host/ops/cad-queue.js` 新增（注册父任务 → 逐条 `convertCad` 复用 → 订阅子任务终态 → tick 父任务 → 终态判定）。订阅用子任务自己的 `TaskStore.subscribe`（已有 emit 机制），**不新增轮询**。

## 4. 其余电网图型（六类）

### 4.1 决策：扩展 visio-grid.ps1 框架，不建新引擎

| 方案 | 结论 |
|---|---|
| A. 扩展 `visio-grid.ps1`（新 kind 分支 + 新布局函数） | **采用** |
| B. 新建独立引擎（如 visio-grid2.ps1） | 否决 |

理由（已核实）：
1. `visio-grid.ps1` 已沉淀：COM 生命周期管理（AlertResponse/Quit/进程清理，三次实跑无残留）、符号注入→实例绘制→Group→连线→自动缩放→SaveAs(.vsdx/.vsd 回退)、错误映射与 300s 超时——新引擎需重复约 600 行且重新承担真机验证成本；
2. 新六类图的差异**只在布局算法与少数基元**（表格、箭头、多页），绘制基元全部复用；
3. 单文件膨胀风险 → 把新布局函数拆到 `engines\visio-layouts.ps1`（六类布局函数），`visio-grid.ps1` 在 kind 分派处 `dot-source` 引入（P2 已用同款 `office-com.ps1` dot-source 模式）；失败时错误归并 E2023（带布局步骤上下文）。

### 4.2 模型校验扩展（`grid-model.js`）

- `GRID_KINDS` 扩为 9：`singleLine | distribution | networkTopology | protection | substationPlan | geoNetwork | powerFlow | terminalStrip | cableRoute`（cableRoute 本期 P3 不实现 → 校验报 `E2024 GRID_KIND_NOT_IMPLEMENTED`，模型 schema 仍写入文档供 P4）。
- 新类各一个校验函数（结构 error → E2021；warn/info 接线提示沿用既有 codes）：
  - protection：`circuits[].devices[]` 引用存在、`terminalStrips[].terminals[].ref` 非空、loops 端点（`id.触点` 或设备 id）存在；
  - substationPlan：zones/items 坐标有限数、item 在 plot 范围内（warn，不阻断）；
  - geoNetwork：`viewport` 四值合法（west<east, south<north）、stations/lines 端点存在、points 途经点形如 `[lng,lat]` 或 `["站id", null]`；
  - powerFlow：`levels[]` 电压正数、buses/nodes 的 level 引用存在、flows 端点存在且 `direction` 可选格式 `"A→B"|"A-B"`、transformers 跨层（info 提示电压不匹配时 warn）；
  - terminalStrip：strips/terminals 结构、`columns ∈ 1|2`、`type ∈ normal|test|shorting|ground`、`link` 引用同 strip 内端子号。
- 符号实例上限沿用 `gridMaxSymbols`（2000）。

### 4.3 统一底座（不变，P2 §4.1）

新六类图沿用统一底座 `{kind, title, meta{paper,standard,scale}, nodes[], links[]}` + 类型专属字段（见各节 schema）。`links[].kind` 增加 `'flow'`（潮流箭头线）。默认连线规则：protection 的 circuits 内串接；其余类无默认连线（显式为主）。

### 4.4 六类 schema 与布局算法

#### ① protection（二次回路/继保原理图）—— P3 简版

```jsonc
{
  "kind": "protection",
  "title": "110kV 线路保护电流回路图（示例）",
  "meta": { "paper": "A3-landscape", "standard": "GB/T 4728-2022" },
  "circuits": [                       // 回路 = 一条水平设备链（简版：每个回路一行）
    { "id": "C1", "label": "电流回路", "voltage": "DC110V",
      "devices": [
        { "id": "TAa", "symbolRef": "gb4728.6.TA", "label": "1TAa" },
        { "id": "KA1", "symbolRef": "gb4728.7.KCOIL", "label": "KA1" },
        { "id": "XT1.1", "symbolRef": "gb4728.3.XT", "label": "X1:1" }
      ] }
  ],
  "loops": [                          // 触点/回路间映射（简版：跨行虚线 + 标签，不做触点编号管理）
    { "id": "L1", "from": "KA1", "to": "KM1", "kind": "signal", "label": "KA1-1" }
  ],
  "terminalStrips": [                 // 端子排带（画在回路区上/下边缘）
    { "id": "XT1", "label": "端子排 1X", "side": "top", "terminals": [ { "no": 1, "ref": "A411" }, { "no": 2, "ref": "B411" } ] }
  ]
}
```

布局算法（`Invoke-ProtectionLayout`）：
1. 行 = circuit 一条，自上而下排列，行距 `circuitRowGap`（默认 40mm）；行首画回路名文本框（竖直居左）。
2. 每行内 devices 自左向右串接：首设备 x=回路名后 30mm，设备间距 `deviceGap`（默认 12mm）；设备旋转使两端子水平（沿用 `Get-DeviceRot`）。
3. 端子排带：`side=top` 的画在首行上方、`bottom` 在末行下方；带内端子号从左到右等距（间距 12mm），端子符号 `gb4728.3.XT`（圆圈）+ 号文本；回路设备与端子间用 `links` 显式连线（无自动连）。
4. loops：两端设备实例端子取中点 → 虚线（`LinePattern` 虚线，失败降级实线）横跨各行，label 中点上方。
5. 整体缩放适配（P2 步骤 8）+ 每符号 Group（沿用）。

**分期**：P3 交付简版（回路串行 + 端子带 + 触点映射虚线）；**延后 P4+**：回路展开（电流/电压/控制回路分区、触点编号表、电缆连线表）、横排/竖排混合布局。

#### ② substationPlan（变电站总平面布置示意图）—— P3（绝对坐标/网格模式）

```jsonc
{
  "kind": "substationPlan",
  "title": "110kV 白云变总平面布置示意图",
  "meta": { "paper": "A3-landscape", "compass": true },        // compass: 北向箭头
  "plot": { "widthMm": 800, "heightMm": 600, "gridMm": 50 },   // 场区外框（mm）
  "zones": [
    { "id": "Z1", "label": "110kV 配电装置区", "xMm": 0, "yMm": 0, "widthMm": 300, "heightMm": 200 },
    { "id": "Z2", "label": "主变区", "xMm": 300, "yMm": 0, "widthMm": 200, "heightMm": 200 },
    { "id": "Z3", "label": "综合楼及生活区", "xMm": 0, "yMm": 200, "widthMm": 500, "heightMm": 200 }
  ],
  "items": [                            // 绝对坐标（mm，原点=场区左上）；缺坐标时按 zone 网格吸附
    { "id": "T1", "label": "1# 主变", "symbolRef": "gb4728.6.T2", "xMm": 350, "yMm": 60, "rot": 0 },
    { "id": "RD1", "label": "进站道路", "xMm": 0, "yMm": 400, "widthMm": 500, "heightMm": 24, "primitive": "rect" },
    { "id": "F1", "label": "站区围墙", "xMm": 0, "yMm": 0, "widthMm": 800, "heightMm": 600, "primitive": "rect", "dashed": true }
  ],
  "links": [ { "id": "L1", "from": "T1", "to": "B1", "label": "进线构架" } ]
}
```

布局算法（`Invoke-SubstationLayout`）：
1. 画场区外框（plot 尺寸）与网格线（gridMm 间隔，浅灰、失败降级无网格）；`meta.compass` 时右上角画北向箭头（基元）。
2. zones：按绝对坐标画矩形 + 区域内顶部居中 label；zone 缺坐标时按「从左到右、满行换行」自动排（行高取该行最大 height）。
3. items：有 `xMm/yMm` 直接放置（原点=场区左上，y 向下）；无坐标时按 `zone` 字段（可选）在该 zone 内网格吸附（取 zone 左上 + 网格增量排布）。
4. `primitive:'rect'` 的图元直接画矩形（道路/围墙/沟道），无符号依赖。
5. 连线/缩放/Group 沿用底座。
**分期**：P3 交付绝对坐标/网格模式；**延后**：从 DWG 底图自动提取、道路自动布线。

#### ③ geoNetwork（地理接线图）—— P3

```jsonc
{
  "kind": "geoNetwork",
  "title": "××供电区 35kV 及以上地理接线示意图",
  "meta": { "paper": "A3-landscape" },
  "viewport": { "west": 112.0, "south": 30.0, "east": 114.0, "north": 32.0 },   // 经纬范围
  "stations": [
    { "id": "S1", "label": "白云变", "symbolRef": "gb4728.9.NODE", "lng": 113.2, "lat": 31.1, "voltage": 110 }
  ],
  "lines": [
    { "id": "LN1", "from": "S1", "to": "S2", "voltage": 110, "label": "白-金 I 回",
      "points": [ ["S1", null], [113.5, 31.3], ["S2", null] ] }                 // 途经点：站 id 或 [lng,lat]
  ],
  "labels": [ { "id": "LBL1", "text": "××工业园", "lng": 113.1, "lat": 30.9 } ]   // 独立地名标签
}
```

布局算法（`Invoke-GeoLayout`）：
1. 投影：等距圆柱（x = (lng-west)/(east-west) × 可用宽，y = (north-lat)/(north-south) × 可用高；y 向下）；全部坐标统一换算到 mm 页面系。
2. 站：`NODE` 符号（约 24×14mm），站名标签右侧；`voltage` 不同可用不同描边线宽（可选，P3 不强制）。
3. 线路：按 `points` 顺序折线（站 id 取站投影坐标），双回线（同 from/to 出现 ≥2 条）自动平行偏移 ±1.5mm；线路 label 沿中段上方；`voltage` 入 label 前缀可选。
4. 无经纬数据时支持平面坐标 `stations[].xMm/yMm`（viewport 省略 → 以坐标包围盒自适配）。
5. 缩放/Group 沿用。
**分期**：P3 交付投影+折线+平行偏移；**延后**：底图（地图图片）叠加与配准。

**分期**：P3 交付分层+潮流箭头+标注；**延后**：潮流宽度映射（线宽随 P 值）、自动拓扑分层（Sugiyama 增强）。

布局算法（`Invoke-TerminalStripLayout`）：

**分期**：P3 全量交付（表格基元为主，无新符号依赖，风险低）。

### 4.5 符号库增补（4 个 JSON，结构/规范同 P2 §4.5）

### 5.2 面板预览接通（client.js，双方案落地，P2 §3.7 设计兑现）

1. **挂载判定（apply 时一次）**：`previewDirect = !!safeService(ctx, 'remote.officeToPdf') && typeof ns.render === 'function'`；注入面板 api 袋 `{ previewDirect, renderPdf, revokePdf }`；DiagTab「预览渲染 officeToPdf」行显示方案标记（A 直连 / B 命令）——P2 §6.3 已设计，P3 落地。
2. **方案 A（直连）**：
   ```js
   const r = await ns.render(path, 'foreground', signal);        // {ok, value:{data, missingFonts, generation}}
   if (!r.ok) throw normalizeThrown(r.error);
   blob = new Blob([r.value.data], { type: 'application/pdf' });
   ```
3. **方案 B（命令兜底）**：`callCommand('suite.preview', { path })` → `{pdfBase64, missingFonts, generation}` → base64 解码（`atob` 分块，64MB 上限防主线程卡顿）→ blob。
4. **缓存**：面板组件内 `Map<key, {url, generation}>` LRU（容量 `previewCacheSize`=5）：命中直接 setState 旧 url；未命中渲染后 put；**淘汰与组件卸载时 `URL.revokeObjectURL`**；`connection/reset` 订阅清空缓存（P1 §0.4 既有 subscribeReset）。
5. **iframe**：`<iframe src={url} class="dso-previewFrame">`（CSS：高 60vh、白底、1px 边框 `--dsw-alias-border-l2`、圆角 md）；`missingFonts` 非空显示角标「缺失字体 N 个（hover 列名）」；渲染失败显示 E2011/PREVIEW_UNSUPPORTED 文案 + 「重试」「改用系统打开」按钮；`pdfUrl` 为空显示占位提示。
6. 入口：DocsTab 阅读区对 6 类扩展名（doc/docx/xls/xlsx/ppt/pptx）显示「页面预览」按钮（P1 的 `data-preview-hook` 保留，用于 P4 可能的宿主侧预览增强）。
