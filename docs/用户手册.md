## 1. 简介与能力总览

### 1.1 这是什么

**dsh-office-suite-for-grid**（显示名：办公·电网绘图套件）是 DeepSeek Harness（DSH）的一个插件，在 DSH Web / Desktop 中提供三类能力：

1. **Office 文档与表格**：读取、结构化编辑、排版、预览与导出 PDF；
2. **Visio 电网绘图**：调用本机 Visio 绘制流程图与 8 类电网专业图，内置 GB/T 4728 系列符号库（17 个符号 JSON）；
3. **CAD 图纸转 PDF**：文件夹多图合并成一个 PDF、单文件多图框自动分割为每图一页，另含图纸目录表与批量队列。

插件为 MIT 开源协议，全部源码、运行时（`runtime\`）、产物（`output\`）都在项目文件夹内，官方 DSH 程序目录零写入。

### 1.2 工作方式：一套逻辑，两个入口

```
对话（AI 调工具）                        面板（点按钮）
  suite_env / office_read / office_edit    文档中心 │ Visio 绘图 │ 图纸转换 │ 设置与诊断
  office_format / office_export / visio_draw        │
        └──────────────┬───────────────────────────┘
                       ▼
          统一操作层 suite\host\ops\*（同一份逻辑）
                       ▼
     引擎：PowerShell 引擎（COM）/ Python venv / 纯 Node PDF 引擎 / 宿主 officeToPdf 服务 / Visio COM
```

- 对话工具与面板命令**共用同一操作层**，因此结果结构、错误码、备份行为完全一致；
- 面板通过远程命令（`suite.*`）调用 Host，命令与工具同源（详见附录 A）。

## 2. 安装

### 2.1 前置条件

| 项 | 要求 | 缺失后果 |
|---|---|---|
| 操作系统 | Windows（PowerShell 5.1 或 pwsh 7 均可；脚本保持 5.1 兼容） | 无法运行引擎 |
| DSH | 0.2.0-rc.0 ≤ 版本 < 0.3.0（`engines.dsh` 门限） | 安装被拒（除非用户显式同意版本豁免，有崩溃风险） |
| Node.js | ≥18（插件随 DSH 运行，无需单独安装运行时） | — |
| Microsoft Word / Excel | 读/编辑/排版需要（COM 引擎） | 可改用 Python venv 引擎（`.doc/.xls` 旧格式除外） |
| Microsoft Visio | 绘图需要（Visio 16 实测可用） | 绘图返回 `E1052`/`E2023` |
| AutoCAD / 中望 / 浩辰 | CAD COM 链路（质量最高） | 走 ODA 或 PDF 级引擎 |
| ODAFileConverter | 无 CAD 时把 DWG 整文件转 PDF | 只能处理已有 PDF（`.dwg` 报 `E1001`） |
| Python 3.9–3.13（3.14 实测可用） | Python 编辑/排版引擎（首次使用时自动建 venv） | 只能走 COM 引擎 |
| 宿主 `officeToPdf` 服务 | 预览与导出 PDF | 返回 `E2012` |

> 可用 `suite_env` 工具或面板「设置与诊断」页一键查看本机各项状态，无需手工排查。

### 2.2 渠道一：市场索引（推荐）

1. 打开 DSH →「插件」→「市场」→「添加索引」；
2. 填入索引地址（**必须逐字一致，全小写、无尾斜杠、不要用 `http://`**）：

   ```
   https://underfacet.github.io/dsh-office-suite-for-grid/index.json
   ```

3. 在发现页找到「办公·电网绘图套件」→ 一键安装（或升级）；
4. 安装完成后按 §2.6 重启 DSH 主程序。

注意事项：

- 市场对索引地址要求「规范形式」且**不允许重定向**，所以不要给 http、大小写变体或带斜杠的写法；
- 索引内容有缓存（默认 10 分钟），发版后**最多等 10 分钟**才能在发现页看到新版本；
- 市场默认选择**最新稳定版**（预发布版本不会被默认选中）；
- 若安装被「版本门」拒绝，说明当前 DSH 版本不在 `engines.dsh` 范围（`>=0.2.0-rc.0 <0.3.0`）——请升级 DSH，或在明确知晓崩溃风险的前提下按 DSH 规则逐个版本对申请豁免。

### 2.3 渠道二：GitHub Releases

1. 打开 `https://github.com/Underfacet/dsh-office-suite-for-grid/releases`；
2. 下载 `dsh-office-suite-for-grid-<版本>.tgz` 与 `SHA256SUMS.txt`；
3. （建议）本地校验：

   ```powershell
   Get-FileHash .\dsh-office-suite-for-grid-0.1.0.tgz -Algorithm SHA256
   # 与 SHA256SUMS.txt 中对应行比对
   ```

4. DSH →「插件」→ 插件管理 → 安装本地包，选择该 `.tgz`；
5. 按 §2.6 重启 DSH 主程序。

Releases 页还可能附带 `index.json`（与市场索引一致）与便携 Python（仅当发布配置启用）；便携 Python 解压到项目 `runtime\python-3.12.x\` 使用，不要提交进 git。

### 2.4 渠道三：npm

```powershell
npm install dsh-office-suite-for-grid
```

或在 DSH 插件管理中按包名 `dsh-office-suite-for-grid` 安装。插件运行时依赖 `pdf-lib`、`pdfjs-dist`（由 npm 解析安装），**离线环境装不上依赖**时会导 CAD/PDF 功能不可用，请改用离线 wheel/vendor 预案或换渠道安装。

### 2.5 渠道四：本地链接安装（`tools\install.ps1`）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install.ps1
```

该脚本是**安装前检查 + 指引**，不会写入任何文件，也不会自行安装插件。它会：

- 检查 `powershell` / `pwsh` / `git` / `node` / `python` / `py` 是否在 PATH；
- 检查 Word / Excel / Visio / AutoCAD / 中望 / 浩辰 的 COM 注册项，未安装的标注「对应引擎自动降级」；
- 打印四种安装方式与安装后的自检命令（`/office-env` 或 `suite_env` 工具）。

真正的链接安装：在 DSH 中让智能体执行

> 用插件管理器把 `E:\工作\2026\20261019Visio插件制作\dsh-office-suite-for-grid\suite` 目录链接安装

即代码留在本目录，只在 DSH 配置中登记一条指向 `suite` 的条目（这是「官方程序目录零写入」的唯一例外）。

### 2.6 安装后必做：重启 DSH 主程序

> **首次安装后必须重启 DSH 主程序（关闭桌面应用再打开），侧栏才会出现「办公·电网套件」面板图标。**

原因（实测结论）：DSH 的客户端模块表在宿主启动时扫描 `dsh.client` 声明，并且「该包不是客户端包」的否定结论会按包名缓存到下次重启。因此：

- 先装过旧版（无 client 导出）再升级时，不重启则面板永远不出现；
- 宿主侧的工具与命令**即时生效**（对话里可直接用），但**浏览器页面需要刷新**才能看到新面板/新命令；
- 升级已安装插件时，插件管理器会拦截「已安装」，需**先移除再安装**；
- 面板配置覆盖层在 `runtime\ui-config.json`，只要不删项目目录，重装/升级后仍在。

### 2.7 卸载

插件管理 → 移除（`remove_bundle`）→ 面板、命令、工具全部消失。随后可直接删除项目目录，`runtime\`（venv、备份、日志）与 `output\`（产物）随之清除。详见 §7.5。

## 3. 对话快速上手

在 DSH 对话中直接说出需求（模型会自动选择工具），或显式要求「用 office_edit 修改 …」。工具参数与面板命令一一对应，完整清单见附录 A。

### 3.0 通用约定

- **返回格式**：工具返回 JSON 文本。成功 `{"ok":true,"result":{…}}`；失败 `{"ok":false,"error":{"code":"E2005","message":"…","hint":"…"}}`。`hint` 是给你的处理建议。
- **路径**：可写绝对路径，也可写相对**会话工作区**的路径。写操作必须落在 2026 边界内（默认 `E:\工作\2026`），否则 `E1021`。
- **备份**：`office_edit` / `office_format`（以及面板的编辑/排版）在修改**之前**自动备份原文件；备份失败会中止操作（`E2008`），不会「无保底」地改文件。
- **导出与新建文件不备份**：`office_export`、目录表、绘图产物都是新文件。

### 3.1 `suite_env` —— 检测本机环境

无参数（`additionalProperties: false`）。

```
检查这台机器能做哪些 Office/Visio/CAD 操作
```

返回引擎探测结果（Word/Excel/PowerPoint/Visio、AutoCAD/中望/浩辰、LibreOffice、Python、ODA，以及 `officeCom`、`venv` 等字段）。用它可以在动手前决定「用 COM 还是 Python 引擎」「能不能画图」「CAD 走哪条链路」。

> 说明：`suite_env` 工具每次实际探测；面板命令 `suite.env` 有 60 秒缓存，传 `{"refresh":true}` 强制重探（重探才会实测 COM 实例化，较慢）。

### 3.2 `office_read` —— 读取 Word / Excel

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | 文件路径（绝对路径或相对会话工作目录），支持 `.doc/.docx/.xls/.xlsx` |

返回要点：

- Word：`result.info = { kind:'docx', paragraphs, tables, headings:[{style,text}], preview:[…] }`（标题取前 200 段、正文预览取前 60 行非空段落）；
- Excel：`result.info = { kind:'xlsx', sheetCount, sheets:[{name, rows, cols, sample:[…]}] }`（每表前 5 行 × 6 列样例）。

示例：

```
读取 D:\资料\施工方案.docx 的大纲和表格数量
```

失败码：`E1041`（命令链路缺 path）、`E1042`（类型不支持）、`E1051`；引擎脚本自身的 `NOT_FOUND` / `UNSUPPORTED_TYPE` / `ENGINE_FAIL` 也会原样返回。

### 3.3 `office_edit` —— 结构化编辑

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | 文件路径；文件不存在时可用 `ops[0]` 的 `{"action":"create"}` 新建 |
| `ops` | object[] | 是 | 编辑指令数组（非空，顺序执行，上限 500 条） |
| `engine` | `"auto"` \| `"com"` \| `"python"` | 否 | 缺省取配置 `officeEngine`（默认 `auto`：COM 优先，不可用降级 Python venv） |

**Word 指令**（`.doc/.docx`）：

```json
{"action":"create","kind":"docx"}
{"action":"paragraph","op":"setText|setStyle|insert|delete|append","at":3,"text":"…","style":"标题 1"}
{"action":"heading","level":1,"op":"setText|insert|delete|setStyle","text":"…"}
{"action":"table","table":1,"op":"setCell|addRow|deleteRow|addColumn|deleteColumn","row":1,"col":2,"text":"…","at":"end"}
{"action":"saveAs","path":"…"}
```

**Excel 指令**（`.xls/.xlsx`）：

```json
{"action":"cell","sheet":"Sheet1","at":"B3","value":1.5,"formula":"=SUM(B1:B2)"}
{"action":"row","sheet":"Sheet1","op":"insert|delete","at":3}
{"action":"column","sheet":"Sheet1","op":"insert|delete","at":"B"}
{"action":"sheet","op":"rename|add|delete","name":"…","newName":"…"}
```

（`cell` 的 `value` 与 `formula` 二选一；`formula` 以 `=` 开头。）

返回：`{outputPath, engine, backup:{id,time,path,…}|null, applied:[{op,index,ok,message?}], stats, engineFallback?, warnings?}`。若中途某条指令失败，引擎策略是**中止后续指令并保存已应用的修改**，逐条结果在 `applied` 里（`ok:false` 那几条就是失败项）。

示例：

```
把 D:\资料\会议纪要.docx 第 1 段改成“2026 年度工作会议纪要”，并在末尾追加一段“（本纪要学会后执行）”
```

对应调用：`{path:"D:/资料/会议纪要.docx", ops:[{"action":"paragraph","op":"setText","at":1,"text":"2026 年度工作会议纪要"},{"action":"paragraph","op":"append","text":"（本纪要学会后执行）"}]}`

失败码：`E2001`（无可用引擎）、`E2004`（打开失败）、`E2005`（指令非法/索引越界）、`E2008`（备份失败，操作已中止）、`E2010`（保存失败）、`E1042`（类型不支持）、`E1023`（文件不存在且未给 create）。

### 3.4 `office_format` —— Word 排版

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | Word 文件路径；**套用模板时目标可以不存在**（将从模板新建） |
| `rules` | object[] | 否 | 排版规则数组（上限 100 条） |
| `styleSet` | string | 否 | 样式集 id（`suite\templates\styles` 或 `runtime\templates\styles` 下的 `<id>.json`，同名用户版优先） |
| `template` | string | 否 | 模板名或 docx 路径（`suite\templates\docs` / `runtime\templates\docs`） |
| `placeholders` | object | 否 | 模板占位符键值，如 `{"标题":"关于 X 的通知","日期":"2026-10-20"}` |
| `scope` | string | 否 | 本工具只接受字符串（缺省 `'all'`）；标题级/段落级范围请改用面板命令 `suite.format` 传对象 |
| `engine` | `"auto"` \| `"com"` \| `"python"` | 否 | 同上 |

规则字段：

```json
{
  "target": "heading|body|page|header|footer",
  "level": 1,
  "font": { "name": "黑体", "sizePt": 16, "bold": true },
  "paragraph": { "lineSpacing": 1.5, "spaceBeforePt": 12, "spaceAfterPt": 6, "align": "center|left|right|justify" },
  "numbering": "chinese|arabic|decimalDot|none",
  "page": { "marginsMm": { "top": 37, "bottom": 35, "left": 28, "right": 26 } },
  "header": { "text": "…", "font": { "name": "宋体", "sizePt": 9 } },
  "footer": { "text": "第 X 页 共 Y 页" }
}
```

- `body` 规则作用于正文段落（非标题段落）；`heading` 规则按 `level` 作用；
- `numbering` 由引擎**在文本前加前缀**实现（中文「一、」/ 阿拉伯「1.」/ 数字点「1.1」/ 无），并做了幂等保护：重复排版不会把编号叠加两层；
- **模板优先于 rules**：一旦指定 `template`，rules 不再应用（模板版式即最终版式）；
- 返回：`{outputPath, engine, backup, styleSet, template, applied:[{rule,target,count,ok}], stats}`。

示例：

```
把 D:\资料\周报.docx 排成公文样式：标题二号宋体居中，正文三号仿宋，行距 28 磅，页边距上37下35左28右26
```

失败码：`E2006`（规则非法 / 路径是目录 / 未给任何规则）、`E2007`（样式集或模板不存在）、`E2008`、`E2001`。

### 3.5 `office_export` —— 导出 PDF

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | 源文件，支持 `doc/docx/xls/xlsx/ppt/pptx` |
| `output` | string | 否 | 目标：目录或 `.pdf` 路径；缺省写到会话工作区 `output\pdf\<原名>.pdf`；重名自动加 `-<时间戳>` |
| `engine` | `"auto"` \| `"officeToPdf"` | 否 | 固定走宿主 `officeToPdf` 服务（缺省 `auto`） |

返回：`{outputPath, size, missingFonts, generation, cacheKey, engine:'officeToPdf'}`。`missingFonts` 非空表示渲染时缺字体（版面可能有差异）。导出是**新文件，不触发备份**；写盘采用「先写临时文件再改名」，失败不会残留半成品。

失败码：`E2012`（宿主无 `officeToPdf` 服务或扩展名不支持）、`E2011`（渲染失败 / 超过 64MB 上限）、`E2013`（写盘失败或被占用）、`E1023`、`E1021`。

### 3.6 `visio_draw` —— Visio 绘图

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `kind` | 字符串枚举 | 是 | `flowchart` \| `singleLine` \| `distribution` \| `networkTopology` \| `protection` \| `substationPlan` \| `geoNetwork` \| `powerFlow` \| `terminalStrip`（共 9 类；`cableRoute` 不在枚举内） |

| `model` | object | 电网 8 类必填 | 电网图数据模型（结构见 §4.3.3；`flowchart` 不使用） |
| `nodes` | array | flowchart 用 | `[{id,label,kind:"start"\|"process"\|"decision"\|"end"}]` |

## 4. 面板使用

### 4.1 打开面板

侧栏图标「办公·电网套件」（面板 id `office-suite`，排序 30）→ 打开主面板。顶部是标题与当前会话状态条：**没有活动会话时**，读取/转换类操作会被禁用并提示「请先在左侧工作区打开一个会话」。页签位置会自动记忆（上次停留的页签）。

四个页签：**文档中心 / Visio 绘图 / 图纸转换 / 设置与诊断**。

### 4.2 文档中心

左右分栏：左侧工作区文件树（240px），右侧阅读与操作区。

#### 4.2.1 文件树

- 根 = 当前会话工作区，逐层懒加载；
- 默认只显示 `doc docx xls xlsx ppt pptx vsdx dwg pdf`，可勾选「显示全部文件」；
- 「浏览其他目录…」用系统目录选择器切到任意目录（外部目录模式下，目录用目录服务导航，文件行由命令 `suite.files` 补齐；命令不可用时退化为「仅目录」）；
- 双击目录展开/收起；目录条目过多时提示「仅显示前一部分」；
- 行选中后右侧阅读区出现「读取」等按钮。

#### 4.2.2 读取

- `.doc/.docx/.xls/.xlsx` → 点「读取」调 `suite.read`：
  - Word：标题大纲（h1–h3 层级）、段落数、表格数、正文预览；
  - Excel：工作表清单、每表行列规模、数据样例表格。
- `.vsdx/.dwg/.pdf` → 仅显示元信息（大小/版本/路径），并提示「该类型预览将在后续版本提供」；
- 另提供「刷新」「复制路径」按钮。

#### 4.2.3 编辑子页

选中 `doc/docx/xls/xlsx` 后，阅读区下方出现「编辑 / 排版 / 预览」三个子页签。编辑子页是**表单化指令队列**：

- Word 表单：指令类型（段落 / 标题 / 表格）、操作（段落与标题 `append/setText/setStyle/insert/delete`；表格 `setCell/addRow/deleteRow/addColumn/deleteColumn`）、位置（1 起）、文本、样式名、标题级别、表格序号、行号、列号；
- Excel 表单：单元格（工作表名、位置如 `B3`、值或公式）、行 insert/delete、列 insert/delete、工作表 rename/add/delete；
- 面板表单不提供 `create` / `saveAs` 指令：新建文档与另存请用工具/命令（`office_edit` 的 `{"action":"create"}` / `{"action":"saveAs"}`）；
- 每条「加入队列」→ 列表显示（可移除/清空）→「应用编辑」调 `suite.edit`；
- 结果区：`已应用 N 条指令`、逐条失败行（红字）、引擎标记（`com` / `python`）、备份路径。

#### 4.2.4 排版子页

表单包含：

| 区域 | 字段 |
|---|---|
| 规则 | 规则目标（标题/正文/页面/页眉/页脚）、级别、字体、字号(pt)、加粗、行距（倍数）、段前/段后(pt)、对齐、编号（中文「一、」/ 阿拉伯「1.」/ 数字点「1.1」/ 无）、页边距（上/下/左/右 mm）、页眉/页脚文本 |
| 预设 | 样式集下拉（来自 `suite.templates`：`名称 · 规则数`；非内置的带 `*`，JSON 无效的带 `(!)`）、模板下拉（非内置带 `*`）、模板占位符键值表（键 + 值，可增删） |
| 范围 | 全部 / 仅指定标题级别（复选 1–3） |
| 动作 | 「应用排版」→ `suite.format` |

- 至少要有「一条规则」或「样式集」或「模板」之一，否则按钮提示先补条件；
- **批量排版**卡片：填/选「目标目录」+ 并行度（自动 / 1–4）→「开始批量排版」调 `suite.format.batch`；只处理目录内 `.doc/.docx`（排除 `~$` 临时文件，不递归，单任务上限 200 个）；进度每 800ms 轮询 `suite.office.status`，可取消（取消走 `suite.office.cancel`），结束时列出失败文件清单（部分失败不中断整体）。并行度「自动」= Python 引擎 4、COM 引擎 1（串行）。

#### 4.2.5 预览子页与导出

- 「渲染预览」：可选扩展名 `doc docx xls xlsx ppt pptx`；
  - **方案 A（直连）**：直接调宿主 `remote.officeToPdf.render`；
  - **方案 B（命令）**：调 `suite.preview`，取回 base64 后转 blob；
  - 页面下方显示当前方案（「渲染方案：直连（A）／命令（B）」）；
  - iframe 内显示 PDF；`missingFonts` 非空时显示「缺失字体 N 个」角标；
  - 预览 blob 走 LRU 缓存（`previewCacheSize`，默认 5 条，显示「预览缓存 n/max」），卸载或连接重置时释放；
  - 失败提示 `E2012`（服务不可用）或 `E2011`（渲染失败/超 64MB），提供「重新渲染」。
- 「导出 PDF」：阅读区与预览子页都有按钮，调 `suite.export`（缺省输出到 `output\pdf`，重名加时间戳）。

#### 4.2.6 自动备份与恢复

**编辑子页**底部的「自动备份」卡片（排版等修改同样会产生备份，在此统一查看）：

- 「刷新备份」→ `suite.office.backup.list`，列出最近备份（时间 / 备份 ID / 大小）；
- 「恢复」→ 该行变成二次确认（「确认恢复该备份？当前版本会先自动备份」+ 确定/取消）→ `suite.office.backup.restore`；
- 恢复成功后提示「已恢复：<路径>」，并返回 `preRestoreBackup`（恢复前自动备份的当前版本）；
- 没有备份时提示「暂无备份（首次修改后生成）」（`BACKUP_NONE`）。

### 4.3 Visio 绘图

#### 4.3.1 图类型下拉

| 选项 | kind | 说明 |
|---|---|---|
| 流程图（P1） | `flowchart` | 节点/连线 JSON |
| 电气主接线图 | `singleLine` | 模型 JSON |
| 配电系统图 | `distribution` | 模型 JSON |
| 通信网络拓扑图 | `networkTopology` | 模型 JSON |
| 二次回路/继保原理图 | `protection` | 模型 JSON |
| 变电站总平面布置示意图 | `substationPlan` | 模型 JSON |
| 地理接线图 | `geoNetwork` | 模型 JSON |
| 潮流图/系统接线图 | `powerFlow` | 模型 JSON |
| 端子排图 | `terminalStrip` | 模型 JSON（可多页） |
| 电缆路径图（P4） | `cableRoute` | **置灰**，提示「P4 提供」（`E2024`） |

#### 4.3.2 流程图

两个文本域：节点 JSON（`id/label/kind`，kind 取 `start|process|decision|end`）与连线 JSON（`from/to`）。「插入模板」填入一组示例。运行前做实时校验：JSON 可解析、节点必有 id/label、kind 合法、id 不重复、连线端点存在。

#### 4.3.3 电网图：模型 JSON + 模板

选中电网 8 类后，界面换成**单个「模型 JSON」文本域**（统一底座 `{kind,title,meta,nodes,links}` + 类型专属字段），点「插入模型模板」按当前类型预填一份可直接运行的示例（8 类各一份，与 `docs/P2-设计.md` §4.1 / `docs/P3-设计.md` §4.4 的 schema 一致）。

要点：

- 模型内 `kind` 必须与下拉所选类型一致，否则行内报「模型 kind 与所选图类型不一致」；
- `meta.paper` 支持 `A4-landscape | A4-portrait | A3-landscape | A3-portrait`（三类电网图默认 A3 横向，端子排默认 A4 横向）；
- `protection` 模板用现有符号（TA/QF/J）表达，因为 P3 设计中的 KCOIL/KA/KB/XT 四个符号尚未随包（符号库仍为 17 个）；
- `symbolRef` 必须存在于符号库，可用值示例：`gb4728.3.BUS`、`gb4728.3.J`、`gb4728.6.T2`、`gb4728.6.G`、`gb4728.6.TA`、`gb4728.6.TV`、`gb4728.7.QF`、`gb4728.7.QS`、`gb4728.7.QSE`、`gb4728.7.QL`、`gb4728.7.FU`、`gb4728.7.F`、`gb4728.7.RING-MAIN`、`gb4728.4.C`、`gb4728.4.L`、`gb4728.2.PE`、`gb4728.9.NODE`；
- 输出路径留空 = 会话工作区 `output\diagrams\` 自动命名；也可「选择目录…」指定。

#### 4.3.4 `validations` 含义

`validations` 是 Host 在绘制前做的**接线/布局提示**，**不阻断绘制**（error 级的结构性错误会在更早阶段直接失败，返回 `E2021`/`E2022`）。展示为「警告（warn，黄）/ 提示（info，灰）」。常见 code：

| code | 级别 | 含义 |
|---|---|---|
| `GRID_ISLAND` | warn | 某电气岛没有电源（`tags.source` / `sources[]`），孤岛运行 |
| `GRID_NO_SOURCE` | info | 模型未标注电源，跳过连通性判定 |
| `GRID_MULTI_SOURCE` | info | 同一电气岛内有 ≥2 个电源（并列/闭环运行） |
| `GRID_SWITCH_OPEN` | info | 存在 `state:"open"` 的开关，已按「断边」处理 |
| `GRID_GROUND_CLOSED` | warn | 接地刀闸处于合位（检修态） |
| `GRID_BUS_SPLIT` | info | 母线分段运行（两端不在同一电气岛） |
| `GRID_RING_CLOSED` | info | 光纤环闭环正常 |
| `GRID_RING_OPEN` | warn | 光纤环未闭环（列出断开的节点对） |
| `GRID_FEEDER_OPEN_END` | warn | 馈线末端无下游连接（末端开路） |
| `GRID_AUTO_LINKS` | info | 按母线/间隔规则自动生成了 N 条连线（显式 links 优先，端点对去重） |
| `GRID_ID_ALIAS` | info | 同一 id 出现在多种角色，按别名处理（不重复绘制） |
| `GRID_CIRCUIT_OPEN` | warn | 保护回路只有 1 个设备，无法形成串接 |
| `GRID_PROTECTION_LOOP` | info | 触点/信号映射（虚线 + 标签）已绘制 |
| `GRID_POWERFLOW_ISLAND` | warn | 潮流图某岛无电源 |
| `GRID_TRANSFORMER_SAME_LEVEL` | warn | 变压器两端接在同一电压等级 |
| `GRID_TRANSFORMER_CROSS_LEVEL` | info | 变压器跨层（记录两端电压） |
| `GRID_PLAN_OUT_OF_PLOT` | warn | 设备区/图元超出 `plot` 场区范围 |
| `GRID_GEO_OUTSIDE_VIEWPORT` | warn | 厂站超出 `viewport` 经纬范围 |

建议做法：warn 逐条确认（多半是模型数据问题），info 多为「引擎已自动处理」的说明，可忽略。

#### 4.3.5 运行与结果

点「绘图」→ `suite.draw`。运行中按钮禁用并显示 spinner。结果区显示：

- 「已保存：<绝对路径>」；
- `stats`：符号数、图形数、连线数、母线/间隔/组合，或回路/端子/端子排/厂站/线路/潮流/电压等级/设备区（按图类型显示）；
- 页数（如端子排分页时）；
- `validations` 列表；
- 运行历史（本次会话最近 5 条）。

### 4.4 图纸转换

#### 4.4.1 场景与输入

| 场景 | 语义 | 输入要求 |
|---|---|---|
| 合并（merge） | 文件夹内多张图纸 → 一个 PDF | `input` 必须是**文件夹** |
| 分割（split） | 单个文件内多图框 → 每图一页 PDF | `input` 必须是**单个文件**（`.dwg` 或 `.pdf`） |

- 「选择文件夹…」用系统目录选择器；「浏览…」打开面板内的图纸文件选择器（只显示 `.dwg/.dxf/.pdf`，可上跳目录）；
- 输入框也可直接粘贴路径；
- 合并场景对 PDF 输入是合法的：目录里只有 `.pdf` 时走 PDF 级引擎；目录内同时有 `.dwg` 与 `.pdf` 时优先处理 `.dwg`（`.pdf` 被忽略并记日志）；
- **注意**：选择器可能列出 `.dxf`，但转换只支持 `.dwg/.pdf`，`.dxf` 会返回 `E1041`。

#### 4.4.2 参数

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| PDF 纸型 | `A4 横向` / `保持原图幅` | A4 横向 | `A4-landscape` = 缩放居中适配 A4 横向；`keep` = 保留原图框尺寸 |
| 排序 | 图号优先（回退文件名）/ 文件名自然排序 | 图号优先 | `drawingNo` / `filename` |
| 并行度 | 自动 / 1–8 | 自动 | `auto` = `min(cpu-1, 4)`，上限 8；**CAD COM 引擎恒为串行** |

#### 4.4.3 进度、日志与取消

点「开始转换」→ `suite.cad.convert`，**立即返回 `taskId`**，随后面板每 800ms 轮询 `suite.cad.status`：

- 状态徽标：排队 / 转换中 / 分割中 / 合并中 / 完成 / 失败 / 已取消；
- 进度条：优先按**图框**（`framesDone/framesTotal`），否则按文件数（`filesDone/filesTotal`），显示百分比与当前文件；
- 运行日志：最多保留 200 行，带时间与级别；
- 「取消」→ `suite.cad.cancel`（`AbortController`；COM 路径以终止子进程兜底，已产出的 PDF 留在临时目录并在日志提示）；
- 完成：显示输出路径 +「复制路径」+「在文档中心查看」（切到文档中心并定位输出目录）。

#### 4.4.4 图纸目录表

「图纸目录表」卡片：

- 输入：`.dwg` / `.pdf` 单文件或目录（「选择目录」/「浏览」/手填）；
- 排序：图号优先 / 文件名；
- 「生成目录表」→ `suite.cad.catalog`（**同步执行**，返回即完成）；
- 结果：输出路径、行数、工作表数、写表引擎（`python` / `csv` 降级）、字段命中率表（图号/图名/图幅/比例/张数 的 `hit/total` 与百分比）；
- 缺省输出：`outputRoot\catalog-<时间戳>.xlsx`；xlsx 写出依赖 Python venv（openpyxl），不可用时降级为同名 `.csv`（仅「汇总」表、无样式，结果里注明）；
- 多来源时：`汇总` 表 + 每个来源文件一个工作表；
- 规模上限：单次 文件 ≤100、图框合计 ≤500（超限报 `E1041`，建议分批）；
- 未提取到任何目录字段 → `E1061`；写盘失败 → `E1062`。

#### 4.4.5 批量队列

「批量队列（多文件/多文件夹）」卡片：

- 条目清单：一行一个路径，「添加文件…」「添加文件夹…」「移除」「清空」；条目数上限 100；
- 规则：合并场景的条目必须是文件夹，分割场景必须是单个 `.dwg/.pdf`；队列内所有条目使用**同一模式与参数**；
- 「开始批量转换」→ `suite.cad.convert {inputs:[…]}`，父任务 `kind='cad.queue'`，每个条目再生成一个普通子任务；
- 进度：条目 `done/total` + 当前条目名 + 每行状态徽标；完成后列出「失败条目」明细（`[序号] 路径 · 错误码 消息`）与每个条目的输出路径；
- 语义：**部分失败不算失败**（任务 `done` + `failures` 清单）；全部失败才是 `failed`（`E1033`）；
- 取消父任务会级联取消所有未终态子任务；单独取消子任务只影响该条目。

## 5. 引擎与降级链

### 5.1 总览

```
Office 读取 / 编辑 / 排版
  ├─ ① COM：Word.Application / Excel.Application（PowerShell 引擎，office-com.ps1）
  └─ ② Python：runtime\venv 内 python-docx / openpyxl（office-python.py）
       选择规则：officeEngine=auto 时 COM 优先；COM 不可用 → Python venv；两者都不可用 → E2001

预览 / 导出 PDF（只读转换）
  └─ 宿主 officeToPdf 服务（doc/docx/xls/xlsx/ppt/pptx）；缺失 → E2012

Visio 绘图
  └─ COM：Visio.Application（visio-flowchart.ps1 / visio-grid.ps1 / visio-layouts.ps1）
       .vsdx 保存；旧版 Visio 回退 .vsd；无 Visio → E1052 / E2023

CAD → PDF
  ├─ ① CAD COM：AutoCAD.Application / ZWCAD.Application / GstarCAD.Application（窗口级打印，质量最高）
  ├─ ② ODAFileConverter：整文件 DWG → PDF
  └─ ③ PDF 级引擎（纯 Node：pdfjs-dist + pdf-lib）
       规则：split 优先 ①（窗口打印）→ ②（整文件后 PDF 分割）→ ③；
             merge 优先 ①（逐文件 extents）→ ②（批量整文件）→ ③；
             输入本身是 .pdf 时跳过 ①② 直走 ③；
             无任何引擎且输入 .dwg → E1001
```

降级发生时，任务日志里记录 `engineFallback`（如 `com → oda → pdf`），诊断页可见当前链路。

### 5.2 Office 引擎选择规则

| `officeEngine` | 行为 |
|---|---|
| `'com'` | 强制 COM；COM 不可用直接报 `E2001`（提示可改配置或传 `engine`） |
| `'python'` | 强制 Python；venv 不健康直接报 `E2001` |
| `'auto'`（默认） | COM 可用 → COM；否则 venv 健康 → Python；否则 `E2001`。降级时结果带 `engineFallback: 'com → python'` |

补充规则（重要）：

- 工具/命令传 `engine` 参数时**以参数为准**（仍会做可用性检查）；
- **降级只发生在「探测/选择」阶段**。COM 执行中途失败**不会**自动改用 Python 重试（COM 可能已部分写盘，双引擎重试会二次修改）——此时返回 `E2004`/`E2010`，提示「备份保留，可换 `engine:'python'` 重试」；
- `.doc` / `.xls` 旧二进制格式**只能用 COM**（python-docx/openpyxl 不支持），请求 Python 引擎会明确报错；
- 兼容分支：Office 2007–2013 的 `SaveAs2` 缺失时回退 `SaveAs`（格式码 51/56）。

### 5.3 Python venv（`runtime\venv`）

- **自动创建**：首次用 Python 引擎编辑/排版时创建，或 COM 不可用时的降级路径触发；含 `python-docx==1.2.0`、`openpyxl==3.1.5`（`suite\requirements-office.txt`），传递依赖 lxml 由 pip 解析；
- **版本标记**：`runtime\venv\SUITE_VERSION` = 当前套件版本；**插件升级后首次使用时自动重建**（标记不匹配）；
- **并发安全**：`runtime\venv.lock` 目录锁（mkdir 原子），持锁期间每 30s 心跳；残留锁 >120s 可被抢占；等待超 120s 报 `VENV_BUSY`（提示可手工删锁目录）；
- **离线兜底**：`runtime\wheels\` 内放 wheel 则 `pip --find-links` 优先离线安装；仍失败 → 提示换便携 Python 3.12（配 `venvPython` 指向其 `python.exe`）；
- **安装超时**：默认 600s（首次下载依赖 1–3 分钟属正常）；
- 失败码：`E2002`（创建/装包失败）、`E2003`（依赖无法安装）。

### 5.4 预览与导出（宿主 `officeToPdf`）

- 仅支持 `doc/docx/xls/xlsx/ppt/pptx`（`OfficeExtension` 不含 `vsdx/dwg/pdf`）；
- 单文件上限 64MB（`previewMaxBytes`，超限 `E2011`）；
- 双方案：A 直连 `remote.officeToPdf.render`（页面启动时判空一次），B 命令 `suite.preview`（走 Host `officeToPdf.convert` 契约，自行实现 `source.read`）；
- 缓存键 = `文件版本(mtime) | generation`；导出为**新文件**，不触发备份、不修改源文件。

### 5.5 Visio

- 引擎在内存中按符号 JSON 组装图形（`DrawPolyline/DrawOval/DrawRectangle` + `Group`），**不依赖本机模具**；
- 端子坐标由引擎内存表维护，连线用 `DrawLine`（**不设置 Visio Connection Points**，连接语义由模型承载）；
- 保存 `.vsdx`；探测到 Visio 2003–2010 时回退 `.vsd`（未实测）；
- 超时 300s；符号实例上限 2000（超限 `E2021`）；`visioVisible:true` 可让 Visio 可见以便调试。

### 5.6 CAD 引擎细节

- **场景 B（合并）**：扫描（排除 `~$*.dwg`、`*.bak`、`*.dwl`、`*.dwl2`、本任务输出）→ 图号优先排序（回退文件名自然序）→ 逐文件转 PDF（COM：extents + A4 横向 + `PlotToFile`）→ 纸型适配（`keep` 跳过）→ 合并；
- **场景 A（分割）**：图框识别（块名清单 + 标准图幅尺寸双重依据，IoU>0.9 去重、嵌套丢弃）→ Z 形平面序 + 图号排序 → 逐框窗口打印（`SetWindowToPlot` + `PlotToFile`）→ 每框一页 → 纸型适配 → 合并；
- **PDF 级**：矢量矩形检测（闭合 4 段正交、边长 ≥20pt、面积 ≥页面积 2%）→ 图幅匹配（`1pt = 25.4/72 mm` × UserUnit）→ 文本坐标还原取图号 → 新页裁剪缩放（先铺白底）→ 排序合并；
- 并行：COM 恒 1；ODA/PDF 级按 `parallel`（`auto` = `min(cpu-1,4)`，上限 8）；
- 防御：单页 64MB 上限、每 50 页检查点保存、pdfjs 对象 cleanup/destroy。

### 5.7 缺失行为对照

| 缺失项 | 影响 | 用户侧表现 |
|---|---|---|
| 无 Word/Excel，且 venv 不可用 | 编辑/排版不可用 | `E2001`（提示装 Office 或重建 venv） |
| 无 Word/Excel，venv 可用 | `.doc/.xls` 不可编辑；`.docx/.xlsx` 可用 Python | 传 `engine:'python'` 处理 `.doc` → 明确报错并提示另存为 `.docx` |
| 无 Visio | 无法绘图 | `E1052` / `E2023` |
| 无 CAD、无 ODA，输入 `.dwg` | 无法转换 | `E1001`（提示装 CAD/ODA 或先导出整图 PDF） |
| 无 CAD、有 ODA | 走 ODA → PDF 级 | 诊断页 ODA 标「降级」；日志记 `engineFallback` |
| 无任何 CAD/ODA，但输入 `.pdf` | PDF 级引擎照常工作 | 合并/分割/目录表均可用 |
| 宿主无 `officeToPdf` | 预览与导出 PDF 不可用 | `E2012`（提示改用系统应用打开） |
| venv 不健康（缺依赖/版本不匹配） | Python 引擎不可用 | `E2001`；诊断页 venv 标「需重建」 |

## 6. 常见问题

### 6.1 装好了，侧栏却没有面板

**排查顺序：**

1. **重启 DSH 主程序**（关闭桌面应用再打开）——90% 是这个原因。客户端模块表在启动时扫描 `dsh.client` 声明，且「非客户端包」的否定结论按包名缓存到重启；先装旧版再升级时尤其明显。
2. 刷新浏览器页面（宿主侧工具/命令已生效，但页面需要刷新才能看到新命令/面板）。
3. 确认面板 id 未被占用：侧栏图标名「办公·电网套件」（order 30）。
4. 确认安装的是 `suite` 目录/整包，而不是只复制了部分文件（`client.js`、`cordis.patch.yml`、`locale`、`icon.svg` 必须随包）。
5. 若面板能出现但页面空白/报错：多为 DSH 版本过低（`slots`/`remote` 服务缺失）。此时插件会降级为「只注册工具与命令」，面板不注册——用对话工具即可，或升级 DSH。

> 升级已安装插件时：插件管理器会因「已安装」而拦截，需**先移除再安装**，然后重启。

### 6.3 预览不可用

现象：预览子页提示「预览服务不可用（E2012）」，或诊断页「预览渲染 officeToPdf」显示「不可用（E2012）」。

- 原因：宿主 DSH 版本未提供 `officeToPdf` 渲染服务，或文件扩展名不在 6 类之内；
- 处理：① 预览与导出都走同一服务，服务不可用时改用系统应用打开文件；② 升级 DSH 到提供该服务的版本；③ 若诊断页显示方案「命令（B）」仍可用，说明是直连命名空间未挂载，命令兜底会继续工作（面板自动选择方案）；
- 若显示「未知」：服务探测未完成或命令不可达（刷新页面后重进诊断页）。

### 6.4 venv 损坏 / 需要重建

适用于：诊断页 venv 显示「需重建」、`E2001`/`E2002`/`E2003`、或升级插件后仍用旧依赖。

1. 关闭所有正在跑的批量排版任务；
2. 删除（或改名保留）`runtime\venv` 目录；
3. 若存在残留锁目录 `runtime\venv.lock`，一并删除；
4. 回到文档中心，对任一 `docx/xlsx` 执行一次编辑或排版（或 `suite.edit`），venv 会**自动重建**并装依赖；
5. 需要指定基础 Python 时：`suite.config.set {"key":"venvPython","value":"C:\\Path\\to\\python.exe"}`；
6. 断网环境：把 `python-docx / openpyxl / lxml` 的 wheel 放进 `runtime\wheels\`，再触发第 4 步；
7. 重建后到诊断页确认 venv「健康」，并显示 `依赖：docx x · openpyxl y`。

> 说明：面板当前**没有**单独的「重建 venv」按钮；venv 生命周期由首次使用、套件版本变化、以及上面的手工清理驱动。

### 6.5 其它常见问题

| 现象 | 原因/处理 |
|---|---|
| 面板提示「请先在左侧工作区打开一个会话」 | 面板的读取/转换需要绑定会话；先在左侧打开或新建会话 |
| 提示「命令不可用，请刷新页面（插件可能已升级）」 | 页面缓存了旧命令表：刷新浏览器页面 |
| 提示「远程服务 xxx 未挂载」 | 宿主未提供对应 remote 命名空间；相关功能禁用，其它功能不受影响 |
| 配置改了没立刻生效 | 配置在下次转换/操作时读取；预览缓存条数需重开预览页 |
| 批量排版有文件失败 | 看失败清单（`{file, code}`）；单文件失败不中断整体 |
| 图纸合并后页序不对 | 改排序为「文件名自然排序」，或校准图号提取（`drawingNoPatterns`/`titleBlockZone`） |
| 分割后某页大片空白 | 图框识别多框/框偏：调 `frameToleranceMm`（建议 1–5）、补 `frameSizes` 非标幅面 |
| 报告问题要提供什么 | 诊断页「复制诊断文本」+ 任务日志（`runtime\logs`）+ 复现步骤（**不要附带涉密图纸内容**） |

## 7. 数据与安全

### 7.1 2026 边界

- 默认边界根 = 项目根上溯两级（本机 `E:\工作\2026`），可用插件配置 `projectRoot` 覆盖；
- **所有写操作**（编辑保存、备份、导出、绘图、PDF、目录表、配置覆盖层）都必须在边界内，越界报 `E1021`；
- **读取**默认也要求边界内；开 `allowExternalPaths:true` 只放宽读取，且会写告警日志（写操作永不放宽）；
- 空路径、非绝对路径经解析后同样过校验。

### 7.2 自动备份（3 份轮换）

- 触发时机：`office_edit` / `office_format` / `suite.edit` / `suite.format` / 批量排版，**在引擎执行之前**（指令/规则校验通过后）；导出、绘图、目录表不备份；
- 目录布局：

  ```
  runtime\backups\
  ├─ index.json                       { "<绝对路径>": [ {id,time,file,name,size}, … 最新在前 ] }
  └─ docs\<md5(小写绝对路径)前 12 位>\<文件名>.<UTC 时间戳>.bak
  ```

- 每文档保留最近 `backupCopies`（默认 **3**）份，写新备份后删除更旧的；索引损坏时按磁盘扫描自愈（并告警）；
- 备份失败 → `E2008` **中止操作**（宁可不动，不可无保底）；
- 恢复：先把当前版本再备份一次（防误恢复二次损失），再回写备份文件；
- 面板路径：文档中心 → 编辑子页底部「自动备份」；命令：`suite.office.backup.list` / `suite.office.backup.restore`。

### 7.3 涉密图纸纪律

- 真实图纸只放 `tests-local\`（git 忽略），公开测试用脱敏自建图；
- `tests-local\` / `图纸例子` 的内容**只做路径引用，不读取入库、不写入日志内容**；
- 任务日志、目录表、诊断文本只记录**路径与统计数字**（行数、命中率、图号等），不复制图纸图形或成段文本；
- `output\`、`runtime\` 全部 git 忽略，不随仓库分发；
- 对外反馈问题时，只提供错误码、诊断文本与统计数字，**不要附图纸本体**。

### 7.4 目录与产物

| 路径 | 内容 | 是否入库 |
|---|---|---|
| `suite\` | 插件本体（代码/引擎/符号/模板/语言包） | 是 |
| `runtime\venv` | Python 环境 | 否（git 忽略） |
| `runtime\backups` | 自动备份 + `index.json` | 否 |
| `runtime\logs` | 运行日志 | 否 |
| `runtime\templates` | 用户样式集/模板 | 否 |
| `runtime\ui-config.json` | 面板配置覆盖层 | 否 |
| `output\diagrams` | `.vsdx` 绘图产物 | 否 |
| `output\pdf` | 合并/分割/导出的 PDF | 否 |
| `tests-local\` | 真实样例图纸（保密） | 否 |

### 7.5 卸载

1. DSH 插件管理 → 移除 `dsh-office-suite-for-grid`（`remove_bundle`）：面板、命令、工具立即消失；
2. 删除项目目录（`...\dsh-office-suite-for-grid`）：`runtime\`（venv/备份/日志/配置）与 `output\` 一并清除；
3. 官方 DSH 程序目录无写入；唯一残留是 DSH 配置里那条指向 `suite` 的登记条目（移除插件时一并清理）。

### 7.6 密钥与凭据

npm token、GitHub PAT 等只存本机（`%USERPROFILE%\.npmrc`、本地 git 配置或 CI Secret），**绝不入库**；仓库 `.gitignore` 已忽略 `.env`/`secrets`/`.gittoken` 等。

## 8. 已知限制

以下均摘自 `docs/兼容矩阵.md` 与各阶段设计文档的实测结论，供使用前预期管理。

### 8.1 CAD（无 CAD 机器）

1. 本机无 AutoCAD/中望/浩辰时，**COM 窗口级打印链路无法运行**，只能用 ODA 或 PDF 级引擎；`.dwg` 且无 ODA → `E1001`；
2. COM 场景 A/B 已交付可执行验收清单（`tools\com-smoke.ps1`），但**未在真机验收**；
3. ODAFileConverter 的 PDF 输出能力随安装版本而异（本机未装，未实测）；
4. 中望/浩辰/旧版 AutoCAD 的 `* To PDF.pc3` 设备名与媒体名（如 `ISO_A4_(297.00_x_210.00_MM)`）随驱动/语言变化，需真机校准（配置 `odaPath`/`pc3` 相关项）。

### 8.2 图框识别与调参

1. PDF 级识别基于「矢量矩形 + 标准图幅尺寸表（16 项，容差 ±2mm + 宽高比 0.5%）」，**扫描件/图片 PDF 无法识别**（`E1012`）；
2. 加密 PDF 不支持（`E1011`）；假定页面 `/Rotate 0`，旋转页未处理；
3. 非标幅面（如 A2+1/2）未收全，需在 `frameSizes` 增补；**不要删默认项**；
4. 真实图签格式多样：`drawingNoPatterns`、`titleBlockZone`、`catalogTitleNameZone`、`catalogScalePatterns` 需在真实 PDF 导出替代品上人工核对后校准（T-05）；
5. COM 路径的图框块名清单 `frameBlockNames` 需用引擎 `listBlocks` 调试输出校准（真机第一跑）；
6. 目录表 COM 级读取（`mode=catalog`）**尚未联调**：失败时有 ODA 则降级 ODA→PDF，否则返回结构化错误并提示先导出整图 PDF；
7. 目录表为同步执行，单次 ≤100 文件 / ≤500 图框，大目录需分批；CSV 降级无样式；
8. 多级子目录递归：合并/排版扫描**不递归**（单层目录）。

### 8.3 Visio 图型与符号

1. **电缆路径图（`cableRoute`）未实现**（schema 已定稿，调用返回 `E2024`，面板置灰），计划 P4+；
2. 符号库为 **17 个** JSON（另有 1 个 P1 示例文件 `gb4728.7/example-qf.json`，加载时自动跳过）；P3 文档中的 `KCOIL`/`KA`/`KB`/`XT` 四个符号**未随包**，`protection` 模板用 TA/QF/J 表达同类图元；
3. 随包加载的 17 个符号其 `standard.clause`（标准条款号）**一律留空**——未与标准原文逐条核对，不臆造条款号；
4. **不设置 Visio Connection Points**：端子坐标为引擎内存表，连线为直线 `DrawLine`；图形正确，连接语义由模型承载；
5. 符号内文字**不随实例旋转**（设备旋转 90° 时代号文字保持水平）；
6. Visio 2003–2010 **未实测**（`.vsd` 回退分支已写，本机 Visio 16 未触发）；
7. 布局不做交叉最小化与绕障；`distribution`/`networkTopology` 为简化算法（分层/环圆），`protection` 为简版（回路串行 + 端子带 + 触点虚线），`substationPlan` 为示意级绝对坐标（非施工图精度），`geoNetwork` 等距圆柱投影未做纬度 cos 校正且无地图底图，`powerFlow` 线宽不随 P 值映射；
8. 多页输出目前仅 `terminalStrip`（`Pages.Add` 已在 Visio 16 实测成功，失败降级单页缩放）；
9. 未实现「挂接单位官方图库（.vss/.vssx）」，符号全部来自内置 JSON。

### 8.4 Office

1. `.doc`/`.xls` 旧二进制格式只能用 COM 引擎编辑（Python 引擎不支持），无 Office 时明确报错；
2. 随包只有 1 个样式集（`templates/styles/default.json`）；**公文/红头等 docx 模板未随包**，需自备放入 `runtime\templates\docs\`；
3. 批量排版：COM 恒串行（`parallel` 实际为 1）；Python 引擎可并行（上限 4）；单任务上限 200 文件、不递归、单层目录；
4. `office_format` 工具的 `scope` 仅接受字符串（默认 `all`）；标题级/段落级范围需用命令 `suite.format` 传对象；
5. 模板与 rules 同时给定时**模板优先**，rules 被忽略；
6. 编辑策略：任一 op 失败即中止后续 op，但**已应用的修改会保存**（逐条结果在 `applied`）；
7. 标题编号通过改文本前缀实现（不改多级列表对象），已做幂等剥离，但复杂文档的自动编号可能被覆盖；
8. COM 会话被用户本机 Office 占用时打开失败（`E2004`）。

### 8.5 预览与导出

1. 依赖宿主 `officeToPdf` 服务；真实服务在页面上**尚未端到端实测**（面板未连接时的已知现象，非故障）；
2. 仅 6 类扩展名；单文件 64MB 上限；
3. `missingFonts` 非空时版面可能有差异（字体缺失，非渲染失败）；
4. 预览缓存为客户端内存 LRU（默认 5 条），刷新页面即清空。

### 8.6 平台与分发

1. **仅 Windows**（依赖 PowerShell 与 COM）；
2. DSH 范围 `>=0.2.0-rc.0 <0.3.0`；低于下界安装被拒（豁免有崩溃风险）；
3. 市场索引缓存 10 分钟；索引 URL 不允许重定向，必须规范形式；
4. 离线环境：npm 依赖（`pdf-lib`/`pdfjs-dist`）与 pip 依赖装不上时需 vendor/wheel 预案；
5. GitHub 托管的 CI **没有** Office/Visio/CAD，COM 冒烟需自托管 runner（`SUITE_COM_SMOKE=1`）。

### 8.7 面板

1. 任务进度以 **800ms 轮询** 为主（`suite.cad.status` / `suite.office.status`）；Host→Client 事件推送（`registerRemoteEvents`）形状未实测，本期未启用；
2. 外部目录模式下若 `suite.files` 命令不可用，只能浏览子目录、看不到文件行；
3. 面板设置表单只覆盖 7 个可写键，其余可写键需用命令（§4.5.3）；
4. `cableRoute` 下拉项置灰不可选（P4）。
