以下结论来自本会话 cordis_inspect_query 实测 + 本机环境实测 + 仓库源码核实。每条标注「已核实」或「待实测」。

### 0.1 officeToPdf Host 服务契约（本次已核实，比 P1 文档更精确；P1 suite.preview 的调用形状需修正）

cordis_inspect_query（host Service.listService service=officeToPdf）实测结果：

| 成员 | 签名 | 说明 |
|---|---|---|
| `generation` | 只读属性 `OfficeToPdfGeneration` | 引擎/字体/配置更换时变化 |
| `convert` | `convert(request: OfficeToPdfRequest, signal?) → Promise<OfficeToPdfResult>` | 纯字节转换，不改源文件 |
| `render` | `@Remote render(workspaceFileScope, path, priority, signal) → Promise<RenderedDocumentBytes>` | 按会话文件授权读取并转换（远程端点） |
| `getGeneration` | `@Remote('generation') getGeneration(signal)` | 读取当前渲染 generation（远程端点名 `generation`） |

类型（已核实，引用自服务契约）：

```ts
type OfficeExtension = 'doc' | 'docx' | 'xls' | 'xlsx' | 'ppt' | 'pptx';   // 不含 vsdx/dwg/pdf
type OfficeToPdfPriority = 'foreground' | 'background';
interface OfficeToPdfRequest {
  readonly extension: OfficeExtension;
  readonly priority: OfficeToPdfPriority;
  readonly source: {
    readonly key: OfficeSourceKey;          // 调用方生成的来源键
    readonly version: string;               // 文件版本（缓存判定用）
    readonly bytes?: number;
    read(signal: AbortSignal, maxBytes: number): Promise<{ bytes: Uint8Array; version: string }>;
  };
}
interface OfficeToPdfResult { pdf: Uint8Array; missingFonts: string[]; cacheKey; generation }
interface RenderedDocumentBytes extends WorkspaceFileBytes { missingFonts: string[]; generation }
```

**结论（已核实）**：
1. `convert` 不接受 `{path, absolutePath, extension, format}`（P1 中 `suite.preview` 预留实现传的就是这个形状，**是错的**，P1 当时未实测）。P2 必须改为契约形状：`{ extension, priority, source: { key, version, read() } }`，`source.read` 由本插件实现文件读取。
2. client 侧预期命名空间：`ctx.remote.officeToPdf.render(path, priority, signal)` 与 `ctx.remote.officeToPdf.generation(signal)`（P1 文档 §4.3 判断正确）。
3. **remote.officeToPdf 命名空间是否挂载 = 待实测**（client 页面未连接，无法直接查 client Service 目录）。佐证（已核实）：安装包 `app.asar`（174MB）内 ASCII 检索到 `officeToPdf` 出现于 19 个 4KB 块，且 Host 端 `@Remote` 方法已存在（dsh-api-remotes 装配可挂载）；P1 已核实安装包 devDeps 声明该贡献。**判定：高概率挂载**，仍按双方案落地（§3.7）。

```
              5a. com    → runPs1('office-edit.ps1'|'office-format.ps1', payload)
              5b. python → ensureVenv → runExe(venvPython, ['office-python.py', '-Json', payload])
              6. 结果规整 + applied 统计 → 7. 失败时提示「备份保留在 runtime\backups」
office_format 工具 / suite.format / 批量 / 面板
        └─▶ ops/office-format.js：rules/样式集/模板解析（§3.3）→ 组装成单文件 payload → 走 office-edit.js 的 3–7 步
```

引擎脚本输入输出统一：`-Json '{"path":..., "ops":[...] | "rules":[...] | "template":{...}, "styleSet":{...}}'`；
输出 `{ok:true, result:{outputPath, applied:[...], stats}}` 或 `{ok:false, error:{code,message,hint?}}`（与 P1 引擎同款 JSON，parseJson 兼容）。

### 3.2 编辑指令模型（`ops` 数组，顺序执行，全量校验后再执行）

**Word（.docx/.doc）指令**：

```jsonc
{ "action": "create", "kind": "docx" }                          // path 不存在时：创建空文档（仅当 ops[0]）
{ "action": "paragraph", "op": "setText"|"setStyle"|"insert"|"delete"|"append",
  "at": 3,                       // setText/setStyle/delete 用（1 起）；insert 表示插入到该位置之前
  "text": "...", "style": "标题 1"|"正文"|"Heading 1"|... }      // 样式名按 NameLocal 匹配，未命中报 E2005
{ "action": "heading", "level": 1|2|3, "op": "setText"|"insert"|"delete"|"setStyle", ... }
{ "action": "table", "table": 1, "op": "setCell"|"addRow"|"deleteRow"|"addColumn"|"deleteColumn",
  "row": 1, "col": 2, "text": "...", "at": "end"|3 }            // 行/列编号 1 起；addRow at:'end'|行号
{ "action": "saveAs", "path": "..." }                           // 另存（可选；缺省覆盖原文件）
```

**Excel（.xlsx/.xls）指令**：

```jsonc
{ "action": "cell", "sheet": "Sheet1", "at": "B3", "value": 1.5|"文本",
  "formula": "=SUM(B1:B2)" }                                    // value/formula 二选一
{ "action": "row", "sheet": "Sheet1", "op": "insert"|"delete", "at": 3 }
{ "action": "column", "sheet": "Sheet1", "op": "insert"|"delete", "at": "B"|2 }
{ "action": "sheet", "op": "rename"|"add"|"delete", "name": "...", "newName": "..." }
```

**校验规则（ops/office-edit.js 的 `validateEditOps(path, ext, ops)`，失败 E2005）**：
- 按扩展名限定指令集（docx 文档指令 / xlsx 表格指令），混用报 E2005；
- 每个 op 的必填字段、索引为正整数、`at` 列名 A–XFD 合法、公式字符串以 `=` 开头；
- **不预读文件做索引越界校验**（避免双读），越界由引擎执行时报 `E2005 EDIT_OP_INVALID（索引 N 超出范围）`，op 级失败记录进 `applied[].ok=false`，**引擎策略：任一 op 失败即中止后续 op 并保存已应用的修改**（部分成功不静默）。

### 3.3 排版模型（rules / 样式集 / 模板）

**FormatRule**：

```jsonc
{ "target": "heading"|"body"|"page"|"header"|"footer", "level": 1,          // heading 时必填
  "font": { "name": "黑体", "sizePt": 16, "bold": true },                    // 字体；name 不存在时引擎告警降级
  "paragraph": { "lineSpacing": 1.5, "spaceBeforePt": 12, "spaceAfterPt": 6, "align": "center"|"left"|"right"|"justify" },
  "numbering": "chinese"|"arabic"|"decimalDot"|"none",                       // 一、（一）1.（1） / 1. 2. 3. / 1.1 1.1.1
  "page": { "marginsMm": { "top": 37, "bottom": 35, "left": 28, "right": 26 } },
  "header": { "text": "...", "font": {...} }, "footer": { "text": "第 X 页 共 Y 页" } }
```

- `scope` 缺省 = all（body 规则应用到正文段落——非标题段落；heading 规则按 level 应用）。
- `numbering` 由引擎**在文本前加前缀**实现（Word COM：改写段落文本前缀；不依赖多级列表对象，保证 Word 2007+ 一致）。幂等保护：文本已含本编号前缀时先剥除再重编号（前缀正则与 numbering 模式对应），避免重复排版叠加编号。
- 校验失败 E2006（未知 target/level 越界/编号模式非法/字体字段类型错）。

**样式集（一键套用）**：= 预定义 rules 数组的 JSON 文件（`suite\templates\styles\<id>.json`），`styleSet` 参数即文件 id；用户可在 `runtime\templates\styles\` 自建同构 JSON 覆盖内置（同名用户版优先）。
内置 2 个（P2 交付，字段与 FormatRule 一致）：
- `official-doc`（公文 GB/T 9704）：标题 2 号小标宋（22pt）居中、正文 3 号仿宋_GB2312（16pt）行距 28pt、页边距 上 37/下 35/左 28/右 26mm、页码页脚。
- `report-standard`：标题 1–3 黑体 16/15/14pt，正文宋体 12pt 行距 1.5，页边距 25.4mm 四周。

**模板（公文/红头文件）**：= docx 骨架文件（`suite\templates\docs\*.docx`，含版式、样式、占位符文本 `【标题】【文号】【正文】【落款】【日期】`）。
- 套用流程：`template` 参数 → 打开模板副本 → 逐段替换占位符（`placeholders` 或留空占位）→ `saveAs` 到 `path`（`path` 不存在时直接新建）。
- 红头文件 = `gongwen.docx`（红头文字 + 版记样式已在骨架内）；批量 + 模板组合时模板优先于 rules。
- 模板库枚举：`suite.templates` 返回内置（builtin:true）+ 用户（runtime\templates\docs，builtin:false）。

**批量排版**（`suite.format.batch`）：`paths[]` 或 `dir`（过滤 .doc/.docx，排除 ~$ 临时）→ 任务注册表 → 逐文件执行与单文件相同的 ops 链（每文件独立备份）→ 进度 tick；`parallel` 默认 1（COM 串行；python 引擎可用 parallel=auto，上限 4）。失败文件不中断整体，日志记 `{file, code}`，任务终态 `done`（带失败清单）或全部失败时 `failed`。

### 3.4 引擎探测 / 选择 / 降级（Office）

**probe.ps1 增强（向后兼容）**：
- 保留 v0.1/P1 全部字段；
- 新增 `officeCom`：`{ word: { present, curVer, comUsable }, excel: { present, curVer, comUsable } }`。
  `comUsable` 实测：`New-Object -ComObject Word.Application`（/Excel）→ 成功即 true，随后 `Quit()`；**仅 `refresh:true` 时执行**（60s 缓存内不重试，避免每次探测拉起 Office）；实例化抛错/超时（每应用 10s）→ false。
- 新增 `venv`：`{ present, dir, healthy, pythonVersion, packages: { docx, openpyxl }, setupError? }`（§3.5 check 输出透传）。

**选择规则（ops/office-edit.js 的 `chooseOfficeEngine`）**：

| 配置 officeEngine | 规则 |
|---|---|
| `'com'` / `'python'` | 强制指定；不可用时直接报错（E2001 + 提示可切换配置） |

**兼容分支**：Word/Excel 2007–2013 的 SaveAs2 缺失 → SaveAs（格式码 51/56，P1 §5.1 既有结论，引擎内 try SaveAs2 → catch SaveAs）；.doc/.xls 旧格式编辑后按原格式保存（COM 按扩展名处理）。

### 3.5 venv 生命周期设计（runtime\venv）

**目标**：项目内自包含、锁定版本、离线兜底、并发安全、插件升级自动重建。

**目录与产物**（全部 git 忽略）：
```
runtime\venv\                 Python 环境（python -m venv 创建）
runtime\venv\SUITE_VERSION    写入当前 suite/package.json version，用于升级判定
runtime\venv.lock\            并发锁（目录存在=持锁，mkdir 原子；超时 120s 视为残留可抢占）
runtime\wheels\               离线 wheel 缓存（python-docx/openpyxl/lxml 的 win_amd64 包；首次联网下载或随 Release 资产发布）
```

**依赖锁定**：`suite\requirements-office.txt`：`python-docx==1.2.0`、`openpyxl==3.1.5`（顶层锁定；传递依赖 lxml 由 pip 解析）。**3.14 wheel 兼容性待实测（T-02）**：ensure 失败时按下面降级链走。

**ensure 流程（ops/venv.js + engines/pyenv.ps1）**：
```
ensureVenv(ctx, config):
  1. 探测候选 Python：config.venvPython（显式）→ probe.python（本机 3.14.7）→ 无 → 便携包检查
  2. 若 venv 存在且 SUITE_VERSION == package.json.version 且 healthy(py check) → 直接返回 {healthy:true}
  3. 否则持锁（runtime\venv.lock 目录）→ 二次检查（防并发）
  4. 重建/创建：python -m venv runtime\venv
  5. pip install -r requirements-office.txt（优先 --find-links runtime\wheels 离线；无 wheel 则联网 pip）
  6. 失败 → 降级链：① 换便携 Python 3.12（runtime\python-3.12.x\，尝试联网下载；断网报 E2003 提示手工放置）
                   ② 报 E2002 PYTHON_SETUP_FAILED（原因 + 手工指引）
  7. 成功 → 写 SUITE_VERSION → healthy 校验（import docx/openpyxl + 版本回读）→ 释放锁 → 返回
```
- **check**：`venv\Scripts\python.exe -c "import docx,openpyxl,sys;print(sys.version)"`，输出结构化 JSON 给 probe 透传。
- 损坏自愈：healthy=false 且目录存在 → 改名 `venv.broken-<ts>` 后重建。
- **进程模型（P2 决策）**：每次操作 spawn 一次 python（`runExe`），冷启动约 0.5–1.5s，满足「常规读写 ≤2s」目标；**常驻 stdio JSON-RPC worker 列为 P3 优化**（总体设计 §11 预留，P2 不做，理由：单文件排版命令本身耗时主导，冷启动占比小）。
- 安全：venv 内 pip 安装仅在用户首次使用编辑/排版时触发；路径全部位于 runtime\ 内（boundary 内）；下载仅面向 python.org / PyPI，记录日志。

### 3.6 修改前自动备份（runtime\backups，backupCopies=3）

**触发**：office_edit / office_format / suite.edit / suite.format / suite.format.batch 每个文件在**引擎执行前**（指令校验通过后）。

**布局与命名**：

**方案 B（兜底）—— `suite.preview` 命令（P2 修正实现）**：

```js
// commands-panel.js suite.preview handler（Host 侧，已核实契约形状）
const service = ctx.get('officeToPdf');                       // §0.1 access.optional 已核实
if (!service?.convert) return fail('PREVIEW_UNSUPPORTED', ...);
const statInfo = await statFile(abs);                          // node:fs 取 size/mtime
const request = {
  extension: ext.slice(1),                                    // 'docx'|'xlsx'|...
  priority: config.previewPriority ?? 'foreground',

    key: abs,                                                 // 来源键（路径即可）
    version: String(statInfo.mtimeMs ?? 0),
    bytes: statInfo.size,
    read: async (signal, maxBytes) => {
      if (statInfo.size > maxBytes) throw new OpsError('E2011', '文件超过预览大小上限');

// → { pdfBase64: Buffer.from(output.pdf).toString('base64'), missingFonts, generation, cacheKey }
```

- 面板 iframe：P1 §4.3 草图照用（blob URL + `<iframe src>` + 卸载 revoke）；`data-preview-hook` 挂载点启用；PDF 字节上限默认 64MB（超限提示改用系统查看）。

### 4.2 模型校验与接线校验（ops/grid-model.js，Host 侧、绘制前执行）

**结构校验（error 级 → E2021 GRID_MODEL_INVALID，阻断）**：
- kind 与专属字段匹配（singleLine 必须 buses/bays；distribution 必须 sources/feeders；networkTopology 必须 rings）；
- id 全局唯一（节点/母线/bay/设备/link/ring 同命名空间）；links.from/to 引用存在（含 `id.terminal` 拆分后终端存在）；
- symbolRef 存在于符号库（loadSymbols 结果；缺失 → E2022 SYMBOL_NOT_FOUND）；
- state ∈ closed|open|unknown；voltage 为正数。

**接线校验（warn/info 级 → 随成功结果返回 `validations`，不阻断）**：
- **电源判定**：节点 `tags.source === true`，或 distribution 图的 `sources[]` 成员（自动视为 source）。
- **连通性分析**：并查集遍历所有导电边（links + 默认连线；开关类符号 state=open 视为断边，closed/unknown 导通）。结果提示：
  - 电气岛不含 `tags.source` 节点 → warn「孤岛：<id>（无电源）」；
  - 同一岛内 ≥2 个电源 → info「多电源并列运行（闭环）」；
  - 环网图（networkTopology rings）→ info「光纤环闭环正常」；环内节点断开 → warn。
- **状态提示**：母线两端岛不同 → info「母线分段运行」；接地刀闸 state=closed → warn「接地刀闸合位（检修态）」。
- 出线/馈线末端无连接 → warn「馈线 <id> 末端开路」。

### 4.3 引擎 `engines\visio-grid.ps1`（内存组装 master，不依赖本机模具）

**输入 payload（Host 组装）**：
```jsonc
{
  "model": { ... §4.1 完整模型 ... },
  "symbols": { "gb4728.7.QF": { ...符号 JSON... }, ... },   // ops 层 loadSymbols 按 symbolRef 注入（已校验）
  "outputPath": "...\\diagrams\\xxx.vsdx",
  "validations": [ ... ]                                       // Host 已算好的接线提示（引擎照画+可附加几何提示）
}
```

**执行步骤**：
1. 换算：符号 JSON 单位 mm → Visio 内部单位英寸（×1/25.4）；页面 = meta.paper（A3-landscape 默认 16.54×11.69in，A4-landscape 11.69×8.27in）；
2. 布局（§4.4 三种算法）→ 每符号实例得到 `{xIn, yIn, rot(0|90|180|270), scale}`；
3. 逐符号绘制 primitives（与 visio-flowchart.ps1 同款 COM 调用）：
   - `polyline/line` → `DrawPolyline`（或逐段 `DrawLine`；closed:true 时闭合）+ `Cells('LineWeight')` 按 stroke mm 换算；
   - `circle` → `DrawOval`；`rect` → `DrawRectangle`；`text` → 独立文本框（`DrawRectangle` + `Text`，或 `DrawLine` 无效果则用 Rectangle 无填充）；
   - 绘制顺序 = primitives 数组顺序（后覆盖先）；
4. 每符号实例绘制完 → `Group()` 成组（可整体移动/复制，出线端仍按实例端子绝对坐标计算）；
5. 端子锚点：**P2 v1 不设置 Visio Connection Points**（COM AddRow 到 Connection Points section 的版本差异大）——端子坐标由引擎内存表维护，连线直接用 `DrawLine`（首尾端点 = 两实例端子换算后的绝对坐标），保证「图形正确、连接语义由模型承载」；Connection Points 优化列 P3。
6. 连线：`line` 直线；`feeder/fiber/cable` 正交走线（先横后竖，两折点）；标签沿线段中点上移 0.1in 放置；
7. 文本标签（设备 label / 母线 label / 间隔名）：文本框 0.1in 字号 8pt（Visio 默认）起步，随 scale；
8. 自动缩放：布局总尺寸超出纸型 → `scale = min(paperW/w, paperH/h)` 整体乘以 scale 再偏移居中；标题 → `page.Name`；
9. `doc.SaveAs(outputPath)`（.vsdx；Visio 2003–2010 探测旧版时输出 .vsd，P1 §5.1 兼容分支）。
10. 输出：`{ok:true, result:{outputPath, format, stats:{symbols, shapes, links, buses, bays}, validations}}`。

**防御**：每个 COM 调用 try/catch 映射 E2023 LAYOUT_FAILED（含步骤上下文）；`-NonInteractive` 运行；超时 300s（复用 runPs1 配置）；符号实例数上限 2000（防模型爆炸，超限 E2021）。

### 4.4 三种布局算法（ps1 内实现，纯几何）

**① singleLine —— 母线横排 + 间隔竖列**：
```
1. buses 按 voltage 降序、同电压按 section 排序 → 行号 r（0 起）；母线 y = marginTop + r × busRowGap（默认 60mm=2.36in）；
   母线线宽 = 图宽（可配置 margin，默认左右各 20mm）；母线 label 放行首上方。
2. 每行母线下的 bays 依序分配 x：x = marginLeft + Σ(前面 bay 的列宽)；列宽 = max(设备符号宽) + 40mm。
3. bay 内设备沿 y 从母线向下依次排：首设备距母线 12mm，设备间距 8mm；设备旋转使两端子连线为竖直方向
   （符号 terminals 决定的默认方向；接地刀闸等竖排符号不旋转）。
4. transformers：两电压等级行之间居中画（双绕组：高压侧朝上/低压侧朝下），x = 两 bay 列中点。
5. busTies：两段母线间的竖直连接列（在段分隔处），设备沿 y 排布。
6. 出线：bay 最末设备再向下延伸 24mm 画馈线并标 label（或 links 显式）。
```

**② distribution —— 分层（Sugiyama 简化）**：
```
1. 层号：sources 层 0；BFS 沿 feeders/links（无向）从电源点遍历 → depth；孤立节点 depth=0 追加。
2. x = depth × columnGap（默认 70mm）；同层节点 y 从 marginTop 起每节点 40mm 递增，整层垂直居中。
3. 环网柜（RING-MAIN 组合符号）尺寸较大（约 48×36mm），列宽取层内最大符号宽。
4. 连线正交走线（从出端水平到中线 → 竖直到目标层 → 水平入端）；馈线 label 沿水平段上方。
```

**③ networkTopology —— 环圆布局 + 径向树**：
```
1. 每个 ring：节点按 ring.nodes 顺序均匀分布在圆上，圆心 = 该环分配的中心点（多环并排/网格排布），
   半径 = max(45mm, n × 22mm / (2π))；环线 = 相邻节点直线段（多边形近似）+ 首尾闭合。
2. 非环节点：BFS 从环上节点向外分层，沿径向向外放置（角度 = 挂接环节点角度，半径 + 每层 30mm）；
   无环图（全 links）退化为 distribution 分层。
3. 节点符号 NODE（约 24×14mm）不加旋转；环 label 置于环内空白处。
```

布局完成后做 4.3 步骤 8 的整体缩放适配。
