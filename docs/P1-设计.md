- 版本：P1-v1.0（可直接指导 flash 子智能体编码）
- 日期：2026-10-20
- 基线：DSH 0.2.1-rc.2（`engines.dsh: ">=0.2.0-rc.0 <0.3.0"`）

### 0.1 插槽：`sidebar.panellist` 与 `main`（全部已核实）

- `sidebar.panellist` 由 `sidebar` 插槽注册声明：`{ name:'sidebar.panellist', kind:'list', scope:'root' }`；侧边栏用
  `ctx.slots.entriesOfSlot('sidebar.panellist')` 读取条目，按 `options.order` 升序渲染，`label` 经
  `resolveSlotLabel(options.label)` 解析（接受字符串或 `() => string` 函数，缺省回退 `id`）。
- **注册项完整选项**：`{ name:'sidebar.panellist', id:'<panelId>', order:<number>, label:() => string, locale:NS }`。
  该条目的**组件只渲染图标字形**，props 为 `{ size: 16|18, active: boolean }`（展开/收起两种尺寸）。
- 点击侧栏图标 → `ctx.layout.selectPanel(id)`（`selectPanel(null)` 返回会话区；`selectPanel` 会校验 `main` 插槽中
  已注册 `options.key === id` 的条目，否则抛错）。
- `main` 是**键控（keyed）插槽**：`{ kind:'keyed', scope:'root' }`（由 layout 插件在 `root` 注册声明）。
  渲染规则（AppFrame）：`renderSlot('main', {}, { entryKey: activePanelId ?? 'conversation' })`。
  即：`main` 面板的注册 `options.key` 必须与 `sidebar.panellist` 条目的 `id` 相同；无面板激活时 key 恒为 `'conversation'`。
- **已占用的 key/id**（勿用）：`'conversation'`（会话主视图）、`'plugins'`（插件管理面板，panellist order=0）、
  `'schedules'`（定时任务面板）。本项目使用 **`PANEL_ID = 'office-suite'`，order = 30**。
- 官方完整范例（插件管理器面板）注册方式：
  ```js
  ctx.slots.inject('main', function* () {
    yield ctx.slots.register({
      name: 'main', key: PANEL_ID, locale: NS, store, inject: () => face,
      children: { /* 面板内嵌子插槽声明 {kind, scope}，本项目 P1 不需要 */ }
    }, PanelComponent);
    // 可选：订阅 panelInfo 在离开面板时重置视图
    yield ctx.layout.panelInfo.subscribe(() => { /* activePanelId 变化处理 */ });
  });
  ctx.slots.inject('sidebar.panellist', () => ctx.slots.register({
    name: 'sidebar.panellist', id: PANEL_ID, order: 30, label: () => t('panel.title'), locale: NS
  }, PanelGlyph));
  ```
- slots 服务 API（本项目将用到的最小集）：`ctx.slots.inject(slotKey, factoryOrGenerator)`（可等待插槽声明，generator 内
  `yield register(...)`）、`ctx.slots.register(options, Component)`、`ctx.slots.subscribe(slotKey, listener)`、
  `ctx.slots.entries(slotKey)` / `entriesOfSlot(slotKey)`、`ctx.slots.getVersion(slotKey)`、
  `ctx.slots.provideRoot({ hooks, keyedHooks })`。注册选项通用字段：`name`、`id`、`key`、`order`、`label`、
  `locale`（该条目的字典命名空间）、`inject`（`(ctx) => props` 注入函数）、`store`（@deepseek-ai/dsh-client-store 句柄，可选）、
  `children`（子插槽声明表）。
- layout 服务（`ctx.layout`）：`selectPanel(id|null)`、`toggleSidebar()`、`beginNavigation()`、`openRightbar/closeRightbar`、
  `panelInfo`（`{ getSnapshot(): { activePanelId }, subscribe(fn) }`）。

### 0.2 Client 插件格式与模块表（全部已核实）

- 浏览器产物格式（官方模板与全部内置 UI 包一致）：
  ```js
  window.__ModuleLoader__.load({
    id: 'dsh-office-suite-for-grid',            // 与包名一致
    factory(require) {
      const React = require('react');            // 来自浏览器模块表，勿自装 React
      return { inject: [...], apply(ctx) {...} };
    }
  });
  ```
- 浏览器模块表中**可用**的共享模块（官方包均在用）：`react`、`react/jsx-runtime`、`react-dom`、
  `@deepseek-ai/cordis`、`@deepseek-ai/dsh-client-store`、`@deepseek-ai/dsh-client-ui-slots`、
  `@deepseek-ai/dsh-client-ui-primitives`（按钮/图标/Modal/Tooltip 等）、`clsx`、`zod`。
  **P1 约束：本项目 client 只依赖 `require('react')`（与 `react/jsx-runtime` 可选）**，自绘 UI 与图标，
  避免依赖 primitives 的图标命名变动；`dsh.client.external` 留空。
- **ModuleLoader 工厂是单文件闭包产物**：工厂内部不能使用相对路径 import 拆包；多文件只能「单文件内按区域组织」
  （官方包是构建期把多模块打成带 `//#region` 的单文件）。P1 采用单文件 `suite/client.js`，按 `//#region` 分区；
  P2 若组件膨胀再引入 esbuild 从 `suite/client-src/` 打包（可选，不阻塞 P1）。
- package.json 增加：
  ```json
  "exports": { ".": "./index.js", "./client": "./client.js", "./locale/*.json": "./locale/*.json", "./icon": "./icon.svg" },
  "files": [..., "client.js", "engines/*.ps1", "host/*.js", "symbols/**/*.json"],
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web", "immediately": true,
      "inject": ["@deepseek-ai/dsh-api-remotes", "@deepseek-ai/dsh-client-ui-layout",
                 "@deepseek-ai/dsh-client-ui-sidebar", "@deepseek-ai/dsh-client-ui-workspace"] }
  }
  ```
  说明：`dsh.client.inject` 是**预取/加载元数据**（官方注释明确：不决定 apply 顺序）；真正的服务依赖写在
  client.js 导出的 `inject` 数组里。`immediately: true` 让面板在启动即注册（侧栏图标立即可见）。
- **本项目 client.js 的 `inject`**（服务键，官方同款写法）：
  `['slots','layout','locale','theme','sessions','uiWorkspace','remote','remote.commands','remote.workspaceFiles','remote.directoryPicker']`
  - `remote.<ns>` 是可注入的 Cordis 服务键（命名空间服务，见 0.4）；对可能缺挂的命名空间用
    `ctx.get('remote.commands')`（带 undefined 检查）防御读取。

### 0.4 面板 → Host 调用路径（全部已核实；一处待实测）

- **Host 命令注册**（v0.1 已用）：`ctx.commands.register({ name, description, input?, handler(invocation) })`；
  `handler` 返回 `{kind:'success', text?}` 或 `{kind:'error', text}`；`invocation = { commandId, agent, rawInput, attachments, signal }`
  （`rawInput` 为命令名之后的整行文本；`agent` 是发起会话的 Agent，可用于 `ctx.workingDirectory.ensure`）。
- **Client 执行**：remote 命名空间 `commands` 提供
  `ctx.remote.commands.execute(line, submittedAttachments, signal?) → {ok:true, value: CommandExecution|undefined} | {ok:false, error: RemoteError}`
  与 `ctx.remote.commands.list(signal?)`。
  线路上 `commands/execute` 的第一个参数是 **`agentId`（lookup 型参数）**——**客户端不传、由网关按调用方 ctx 自动解析**
  （typert contexts 的 Client 适配器提供 identity；解析不到会抛 `requires an agent Context`）。
  因此面板内所有 remote 调用**必须在插件 fiber 的 ctx 上发起**（apply/inject 回调/组件事件里），
  绑定的会话 = 当前主视图会话。
- **Remote 网关机制（已核实，gateway 包 client.browser.js）**：
  - `ctx.remote`（key `'remote'`）由 `@deepseek-ai/dsh-api-gateway` 提供；`@deepseek-ai/dsh-api-remotes`
    （inject `['remote']`）在 apply 中把本装配选定的贡献逐个 `ctx.remote.$mount(contribution)`；
    每个端点 `ns/method` 生成命名空间服务 `remote.<ns>`（可注入）。
  - **所有 remote 调用统一返回结果包装**：`{ok:true, value}` 或 `{ok:false, error}`，`error` 为
    `RemoteError`（`{ code, message, details }`，`throw result.error` 保持抛出语义）。
    取消 → `code:'gateway/cancelled'`；传输故障 → `code:'gateway/internal'`。**写码时必须 `if (!result.ok)` 展开**。
  - lookup 型参数（`workspaceFileScope`、`agent`）在 `prepareInvocation` 中从业务参数里扣除，客户端只传业务参数 +
    可选 AbortSignal；identity 由 `typert.contexts.getClient(kind).identity(callerCtx)` 解析。
- **workspaceFiles 命名空间（契约已核实）**——客户端调用形态（scope 参数自动注入，不传）：
  - `ctx.remote.workspaceFiles.list(path, signal?)` → `{ok, value: {path, entries: [{name, type:'file'|'directory'|'other', size?}], truncated}}`（仅会话工作区内目录）
  - `ctx.remote.workspaceFiles.read(path, {offset?, limit?}, signal?)` → `{ok, value: {offset, text, lines, eof, absolutePath, version, bytes?}}`
  - `ctx.remote.workspaceFiles.readBytes(path, {range?, baseFile?}, signal?)` → `{ok, value: {offset, data: Uint8Array, eof, absolutePath, version, bytes?}}`
  - `ctx.remote.workspaceFiles.stat(path, signal?)` → `{ok, value: {absolutePath, version, bytes?}}`
  - `ctx.remote.workspaceFiles.changes(path, signal?)` → 流式（`{kind:'ready'}` / `{kind:'change', change}`）
- **directoryPicker 命名空间（已核实）**：`pick(signal?)` → `string|null`；`list(path|undefined, signal?)` →
  `{path, home, crumbs, entries:[{name,path,hidden}], truncated}`；`createDirectory(path, name)` → 新目录绝对路径。
  `remote.directoryPicker` 是本装配必挂命名空间（官方 ui-workspace 插件注入 `'remote.directoryPicker'`，缺挂即无法加载）。
- **officeToPdf（Host 契约已核实；remote 命名空间挂载待实测）**：
  Host 服务契约：`convert(OfficeToPdfRequest, signal?) → {pdf: Uint8Array, missingFonts: string[], cacheKey, generation}`；
  `@Remote render(workspaceFileScope, path, priority:'foreground'|'background', signal) → RenderedDocumentBytes`
  （= WorkspaceFileBytes + `missingFonts` + `generation`）；`@Remote('generation') getGeneration(signal)`。
  客户端预期形态：`ctx.remote.officeToPdf.render(path, priority, signal)` / `ctx.remote.officeToPdf.generation(signal)`。
  注：`OfficeExtension` 仅 `doc|docx|xls|xlsx|ppt|pptx`，**不含 vsdx/dwg/pdf**。
  **待实测**：本装配 dsh-api-remotes 是否挂载 `officeToPdf` 命名空间（安装包 devDeps 已声明该贡献，属高概率挂载）。
  候选方案 A（首选）：运行时 `ctx.get('remote.officeToPdf')` 判空，存在即用；候选方案 B（兜底）：面板预览统一走本插件
  远程命令 `suite.preview`（Host 内直接调用 `ctx.officeToPdf.render` 契约，返回 PDF 字节 base64），预览接入点设计不依赖命名空间形式。
- **Host → Client 事件推送（部分待实测）**：Host 侧 `ctx.typertGateway.registerRemoteEvents(source, hostInfo)` 可注册转发事件，
  Client 侧 `ctx.remote.$on('事件名', listener)` 订阅（官方 plugin-manager 用法：`ctx.remote.$on('plugin-manager/changed', ...)`）。
  事件源构造的具体形状**待实测**。P1 采用**轮询为主 + 事件为辅**：
  ① 面板对 `suite.cad.status` 每 800ms 轮询（任务结束停止）——保证可用；
  ② Host 尝试注册 `office-suite/task-progress` 转发事件，面板 `$on` 订阅到首帧即切换为事件驱动；注册失败静默降级为纯轮询。
- 连接复位：`ctx.on('connection/reset', refresh)`（官方用法）用于重连后刷新面板状态。

### 0.5 面板文件浏览与状态（已核实）

- `uiWorkspace` 服务（Cordis `Service`，key `'uiWorkspace'`，官方 ui-workspace 插件提供）：
  - `pickDirectory(): Promise<string|null>`（内部调 `remote.directoryPicker.pick()`，已 unwrap，失败抛错）
  - `listDirectory(path, signal): Promise<DirectoryListing>`（内部调 `remote.directoryPicker.list`，已 unwrap）
  - `createDirectory(path, name): Promise<string>`
  - 另有 `startSession/openSession/forkSession/archiveSession/unarchiveSession/pinSession/unpinSession`（P1 不用）
- 当前会话判定（官方用法）：`ctx.sessions.list.getSnapshot()` → `{ ids, byId }`，
  当前主视图会话 = `Object.values(byId).find(row => (row.retainedBy.mainView ?? 0) > 0)`。
  无当前会话时，agent 绑定的命令（commands/workspaceFiles）不可用 → 面板显示引导文案（见 §2.4）。
- 文件浏览策略：**会话工作区内**用 `remote.workspaceFiles.list`（受会话作用域保护）；
  **任意目录**（tests-local、图纸例子、选择输出目录）用 `uiWorkspace.listDirectory` / `pickDirectory`。
  两者返回值形状不同（前者 `entries:[{name,type,size?}]`，后者 `entries:[{name,path,hidden}]`），面板抽象成统一 `FsEntry` 再渲染。

### 1.4 状态与事件流

```
用户点击侧栏图标 ──▶ layout.selectPanel('office-suite')
                       │ main 插槽按 key='office-suite' 挂载 OfficeSuitePanel
                       ▼
组件内事件 ──▶ callCommand(name, args, signal)
              │  1. line = '/' + name + ' ' + JSON.stringify(args)
              │  2. r = await ctx.remote.commands.execute(line, [], signal)   // agentId 由网关自动绑定当前主视图会话
              │  3. r.ok===false → 抛 RemoteError(code/message)（gateway/cancelled=用户取消）
              │  4. value===undefined → 命令不存在（升级插件后旧会话提示刷新）
              │  5. value.result.kind==='error' → 抛 { code, message, hint }（来自 Host ops 层）
              │  6. value.result.kind==='success' → JSON.parse(text) → {ok, result} | {ok:false, error}
              ▼
Host 命令 handler(rawInput, invocation.agent) ──▶ ops 层（boundary 校验 → 引擎 runPs1/Node PDF 引擎）
                                                     │
   长任务（cad.convert）：tasks.js 注册 {taskId, state, progress, abort}
       面板轮询 suite.cad.status（800ms）◀──────┘  （可选）typertGateway 事件 → ctx.remote.$on 首帧升级
```

状态管理约定（P1 不引第三方状态库，官方 `@deepseek-ai/dsh-client-store` 可用但非必需）：
- 每页签内部用 React `useState/useEffect` + `useRef`（轮询句柄、AbortController）；
- 跨页共享：当前会话 id 每次渲染从注入的 `currentSessionId()` 现算（sessions 为响应式 store，面板外壳用
  `ctx.sessions.list.subscribe` 驱动重渲染）；任务进度通过 `subscribeProgress` 广播到 CadTab 的本地 state。
- 轮询生命周期：组件卸载 / 任务终态（done|failed|cancelled）时 `clearInterval`；信号用 `AbortController` 联动取消。

## 2. Host 侧远程命令清单（P1 新增；与对话工具共用操作层）

约定：命令名**小写、无前导斜杠**；参数为单个 JSON 文本（`rawInput`）；返回统一为
`{kind:'success', text: JSON.stringify({ok:true,result}|{ok:false,error})}` / `{kind:'error', text}`。
`invocation.agent` 用于 `sessionCwd`；路径先过 `boundary.js` 校验（§5.3）。
所有操作函数与对话工具同源（tools 的 execute 与命令 handler 调同一 ops 函数）。

| 命令名 | 参数 JSON | 成功 result | 错误 code（示例） |
|---|---|---|---|
| `suite.env` | `{}` 或 `{refresh:true}` | probe 引擎探测缓存（含 Word/Excel/Visio/CAD/ODA/Python 字段） | `ENGINE_FAIL` |
| `suite.read` | `{path, mode?:"outline"\|"full"}` | office_read 同款结果（Word 大纲/表格数/预览，Excel 工作表清单+样例） | `PATH_OUTSIDE_ROOT`、`ENGINE_FAIL`、`FILE_UNSUPPORTED` |
| `suite.draw` | `{kind:"flowchart", title?, nodes, edges, outputPath?}` | `{outputPath, stats:{nodes,edges}}` | 同上 + `VISIO_UNAVAILABLE` |
| `suite.files` | `{path?, extensions?}` | `{path, entries:[{name,type,size?}], truncated}`（工作区内目录） | `PATH_OUTSIDE_ROOT`、`LIST_FAILED` |
| `suite.cad.convert` | `{mode:"merge"\|"split", input, output?, paper?:"A4-landscape"\|"keep", sort?:"drawingNo"\|"filename", parallel?:"auto"\|1..8}` | `{taskId}`（异步启动，立即返回） | `CAD_NO_ENGINE`、`PATH_OUTSIDE_ROOT`、`INPUT_NOT_FOUND`、`PARAM_INVALID` |
| `suite.cad.status` | `{taskId?}` | 无 taskId：任务列表摘要；有：`{taskId, state, progress:{filesDone,filesTotal,framesDone,framesTotal,currentFile}, log:[{t,level,msg}], output?, error?}` | `TASK_NOT_FOUND` |
| `suite.cad.cancel` | `{taskId}` | `{state:"cancelled"}` | `TASK_NOT_FOUND`、`TASK_NOT_CANCELLABLE` |
| `suite.config.get` | `{}` | 有效配置（Config 合并 UI 覆盖项 `runtime\ui-config.json`） | — |
| `suite.config.set` | `{key, value}`（白名单键：outputRoot/parallel/pdfPaper/sortMode/allowExternalPaths/odaPath） | 写后完整有效配置 | `CONFIG_INVALID_KEY`、`CONFIG_INVALID_VALUE` |
| `suite.preview`（预留） | `{path}` | `{pdfBase64, missingFonts, generation}`（走 Host `officeToPdf` 服务契约；P2 启用） | `PREVIEW_UNSUPPORTED` |

实施要点：
1. `suite.env` 与 v0.1 的 `office-env` 共存（office-env 保持原样），env 探测增加「缓存 60s + `refresh` 强刷」。
2. `suite.cad.convert` handler 只做校验 + 注册任务 + 异步启动（`setTimeout(0)` 起任务，不用 await 卡住命令返回）；
   任务进度写入 `tasks.js` 注册表；日志环形缓冲（200 行/任务）。
3. `suite.cad.status` 是面板轮询的稳定端点——**不依赖 §0.4 待实测的事件推送**即可完成 P1。
4. 操作层签名统一：`ops.xxx(ctx, args, exec) → Promise<{ok,result}|{ok:false,error}>`；
   工具 `execute(args, exec)` 直接 await ops；命令 handler 解析 rawInput JSON 后 await ops，再 `JSON.stringify` 进 `text`。

## 3. CAD→PDF 引擎架构

### 3.1 引擎探测与降级链

探测（`probe.ps1` 增强 + `cad.engine` 选择器）：

```
输入 .dwg（场景 A/B）
  ├─ ① CAD COM：AutoCAD.Application / ZWCAD.Application / GstarCAD.Application
  │      （ProgID + 版本键探测；本机当前均未装 → 记录 missing）
  ├─ ② ODA 整文件转换：ODAFileConverter(.exe/.bat)（config.odaPath 或常见安装路径探测）
  │      整文件 DWG→PDF（不分割）→ 交 PDF 级引擎处理
  └─ ③ PDF 级引擎（纯 Node，pdfjs-dist + pdf-lib）：直接吃“已有 PDF”输入
          （无 CAD/ODA 时，允许 input 指向 .pdf；.dwg 则报 CAD_NO_ENGINE）
```

选择规则：场景 A 优先 ①（窗口级打印，质量最高）→ ②（整文件后 PDF 分割）→ ③；
场景 B 优先 ①（逐文件 extents 打印）→ ②（批量整文件）→ ③。降级时在任务日志中写
`engineFallback: com → oda → pdf` 并在 diag 页标记「当前链路」。
版本兼容：AutoCAD 2010+ 内置 `DWG To PDF.pc3`；旧版需自带 pc3（config 可指向）；中望/浩辰同构
（各自 `* To PDF.pc3`），COM 调用均 `late binding`（不引用类型库）。

### 3.2 场景 B（文件夹合并）完整流水线

```
scan(dir)                      排除 ~$*.dwg、*.bak、*.dwl、*.dwl2、已存在的本任务输出
  → 排序 sortOrder(files)      图号优先：对“能读到图号的文件”（COM 路径可读图签属性 / PDF 路径可由图框区文本提取）
                                先按图号自然排序；无图号文件按文件名自然排序（localeCompare numeric:true）追加在后
  → 逐文件转 PDF               引擎 ①：COM 打开→Layout 设置为当前活动 Layout→PlotType=extents→纸型 A4 横向→PlotToFile
                               引擎 ②：ODAFileConverter inDir outDir version type recurse（输出同名 .pdf）
                               并行：COM 串行（单实例队列）；ODA/PDF 级按 config.parallel（auto=min(cpu-1,4)，上限 8）
  → 纸型适配 adaptPaper(pdf)   统一 A4 横向（缩放 fit + 居中 + 白底）；paper:'keep' 跳过
  → merge(pdfs, out)           pdf-lib 逐页嵌入，输出 outputRoot\merged-<时间戳>.pdf；进度事件每文件一次
```

### 3.3 场景 A（合并图纸分割）完整流水线

```
input.dwg
  引擎 ①（COM 窗口打印路径）：
    openDoc → 遍历 Blocks：块名匹配 config.frameBlockNames（默认 ['*图框*','A0','A1','A2','A3','A4','*TK*']）
              + 遍历模型空间矩形实体（图框线），与标准图幅尺寸表比对（双重依据，见 3.4）
    frames = dedupe(cluster(候选图框))    // 嵌套/重叠合并为一个
    frames = sortFrames(frames)           // 图号优先（读图签文本）→ Z 形布局序（按 x 分列，列内 y 降序）
    for each frame:
        layout.SetWindowToPlot(min,max)   // 单位转 mm
        paper = A4 横向（或 frame 原幅面 if paper:'keep'）
        PlotToFile(outDir\frame-<seq>-<drawingNo>.pdf)
    merge(perFramePdfs) → 最终 PDF（书签 = 图号）
  引擎 ②（ODA + PDF 级兜底路径）：
    ODAFileConverter 整文件 → 1 个多页 PDF
      → PDF 级分割引擎（3.5）：每页检测图框矩形 → 裁剪 → 缩放 → 单页 → 图号提取 → 排序 → 合并
  引擎 ③：直接输入已有 PDF 走上述 PDF 级分割。
```

### 3.4 图框识别与图号提取算法（实现细节）

**标准图幅尺寸表（默认，mm，长边×短边，容差 ±2mm 且宽高比容差 0.5%）**：

| 幅面 | 尺寸 | 幅面 | 尺寸 |
|---|---|---|---|
| A4 | 297×210 | A3 | 420×297 |
| A2 | 594×420 | A1 | 841×594 |
| A0 | 1189×841 | A4×3 | 891×210 |
| A4×4 | 1189×210 | A3×3 | 891×420 |
| A3×4 | 1189×420 | A2×3 | 1261×594 |
| A2×4 | 1682×594 | A2×5 | 2102×594 |
| A1×3 | 1783×841 | A1×4 | 2378×841 |
| A0×2 | 1682×1189 | A0×3 | 2523×1189 |

（config.frameSizes 可扩展/覆盖；样例图纸实测校准后固化进默认表。）

**COM 路径识别**：候选 = 块名命中 `frameBlockNames` 的块参照插入点 → 取其范围框 → 与尺寸表匹配；
再与模型空间闭合矩形实体（图框线）结果**取交集加权**（块命中 + 尺寸命中 = 置信度高；仅尺寸命中 = 中，日志告警）。
**PDF 路径识别**（3.5）：矢量矩形检测（见下）+ 同一尺寸表匹配。
**去重聚类**：两个候选框面积交并比 IoU > 0.9 视为同一图框；包含关系（小框在大框内且面积 <50%）判为框内嵌套线，丢弃小框。

**图号提取**（两引擎共用逻辑，`host/ops/drawingNo.js`）：
1. 图签区 = 图框右下象限：x ∈ [0.6,1.0]、y ∈ [0,0.25]（相对图框，可配置 `titleBlockZone`）。
2. 取该区域内文本（COM：Text/MText 实体；PDF：getTextContent 的 transform 还原坐标）。
3. 行合并：y 差 < 0.6×行高合并为行，行内按 x 排序；按 config.drawingNoPatterns 依次匹配：
   默认 `[/／](?:图号|编号|图别)[:：]?\s*([A-Za-z0-9\u4e00-\u9fa5_./-]+)`、
   `/\b([A-Z]{0,4}-?\d{2,5}(?:-\d{1,3})?(?:[A-Z]?\d{0,3})?)\b/`（裸编号，要求至少 4 位数字降低误报）。
4. 取首个命中并清洗；未命中 → `drawingNo: null`（排序回退文件名）。
**排序**：`sort:'drawingNo'` 时按 `drawingNo` 自然序（null 排最后，再按文件名）；
`sort:'filename'` 直接文件名自然序。分割场景先在平面布局序（列优先 Z 形）上稳定排序，再按上述键排序（`Array.sort` 稳定）。

### 3.5 PDF 级分割引擎（`host/ops/pdf-split.js`，依赖 `pdfjs-dist` + `pdf-lib`）

依赖声明：suite/package.json `"dependencies": { "pdfjs-dist": "^4.x", "pdf-lib": "^1.17.x" }`
（bundle 安装时解析；若离线环境装不上，回退 `vendor\` 内手动放置的产物——列为风险 R-07）。

**解析（pdfjs-dist，Node 侧用 `pdfjs-dist/legacy/build/pdf.mjs`）**：
1. `getDocument({ data, disableFontFace: true, isEvalSupported: false })`；
2. 每页 `getOperatorList()` 扫描路径段：维护当前路径点表，检测「闭合 4 段近似正交矩形」：
   - 单 `re`（rectangle）操作；或 4 个 `l`/`c`（直线化后）首尾相接且相邻边夹角 90°±1.5°；
   - 过滤：边长 < 20pt（噪声）；面积 < 页面积 2% 且无尺寸表匹配（标题栏小格）；
3. 候选矩形 → 与 3.4 尺寸表匹配（页坐标点 → mm：`1pt = 25.4/72 mm`，乘页 UserUnit）→ 图框集；
4. 文本：`getTextContent()` 逐 item 用 transform 矩阵映射坐标 → 3.4 图号提取。
**裁剪/缩放/合并（pdf-lib）**：
1. 对每个图框创建新页：目标尺寸 = `paper:'A4-landscape'` 时 841.89×595.28pt，否则图框原始尺寸（保真）；
2. `const [srcPage] = await target.embedPdf(srcDoc, [pageIndex])`；
   计算 `scale = min(targetW/srcW, targetH/srcH)`，`target.drawPage(srcPage, { x:(targetW-srcW*scale)/2, y:(targetH-srcH*scale)/2, xScale:scale, yScale:scale })`；
   先铺白底（`drawRectangle({color: rgb(1,1,1)})`）防透明背景黑边。
3. 结果页按图号排序后 `addPage` 合并，输出单 PDF。
**内存/防御**：单页字节上限 64MB（超限跳帧并在日志告警）；每 50 页 `save` 一次防 OOM；所有 pdfjs 对象 `cleanup/destroy`。

### 3.6 并行与进度推送

- `parallel:'auto'` → PDF/ODA 级 `min(os.cpus().length - 1, 4)`（≥1，上限 8）；COM 引擎恒为 1（单实例串行队列）。
- 任务状态机：`queued → running → converting → splitting → merging → done | failed | cancelled`。
- 进度帧：`tasks.js` 维护 `{taskId, state, progress:{filesDone, filesTotal, framesDone, framesTotal, currentFile}, log[]}`；
  ops 每完成一个文件/图框调 `tasks.tick(taskId, patch)` 并 `log.append`。
- 推送：① 面板 800ms 轮询 `suite.cad.status`（P1 必通路径）；② Host 尝试
  `ctx.typertGateway.registerRemoteEvents(source, hostInfo)` 注册 `office-suite/task-progress`（形状对齐官方
  plugin-manager 的 events 产物；构造失败 catch 并记日志），面板 `ctx.remote.$on('office-suite/task-progress', ...)`
  收到首帧即停轮询。取消：`AbortController` 注入引擎（COM 的 `PlotToFile` 以进程终止兜底：取消即 terminate 子进程，
  已产出 PDF 保留在临时目录并在日志提示）。

### 5.3 边界（写盘仅限 2026）与安全

- `host/boundary.js`：`resolveBoundaryRoot()` = config.projectRoot 非空时用之；否则取插件包目录上溯两级的
  `E:\工作\2026`（= `dirname(dirname(suite))`），`path.resolve` 后大小写不敏感比较前缀。
- 规则：所有 ops 的**输入读取与输出写入**路径（含 outputRoot、临时目录、备份目录）先过
  `assertInsideRoot(abs, {write})`，越界抛 `E1021 PATH_OUTSIDE_ROOT`；`allowExternalPaths:true` 时仅放宽读取
  （输出仍限 2026 内），且每条越界读取写告警日志。
- 临时文件统一 `runtime\tmp\<taskId>\`；备份 `runtime\backups\`（backupCopies）；日志 `runtime\logs\`。
- 引擎子进程一律经 `ctx.subprocess.spawn`（沿用 runPs1 的 stdout/stderr 上限与超时）；COM 引擎用
  `-NonInteractive`，不弹出可见窗口（visioVisible 仅调试）。
- 涉密数据纪律：面板/日志**不复制**图纸内容；日志只记路径与统计数字；tests-local 与图纸例子永入 .gitignore；
  公开测试只用脱敏合成图。
- 卸载 = remove_bundle + 删除项目目录；DSH 程序目录零写入（仅市场/链接安装的登记条目例外，沿用总体设计）。
